    Módulo de Prácticas: Condiciones en JAVA

    ¡Buenas, equipo! Es hora de poner en práctica las estructuras de control que son el cerebro de cualquier programa: las condiciones. En el desarrollo de software profesional, rara vez escribimos código que se ejecuta igual siempre. Nuestra labor es anticipar situaciones y hacer que el programa reaccione de forma inteligente.

    Narrativa del Proyecto: Módulos para "CyberGuard Sentinel"

    Trabajamos para CyberGuard Solutions, una empresa líder en ciberseguridad. Nuestro proyecto actual es "Sentinel", una nueva suite de seguridad integral. Hoy nos han encargado desarrollar varios prototipos de módulos de lógica que tomarán decisiones clave: validar credenciales, clasificar amenazas, aplicar reglas de firewall y gestionar licencias de usuario. Cada ejercicio representa un pequeño componente de este gran sistema. ¡A programar!

    Ejercicios de Consolidación

    1) Módulo de Autenticación: Verificación de Credenciales | Nivel: Fácil

    Objetivo:

    Implementar una lógica de if-else básica para validar un nombre de usuario y una contraseña, reforzando el uso correcto de equals() para comparar String.

    Tarea a realizar:
    1. Crea una clase ModuloAutenticacion.
    2. Dentro del método main, declara dos constantes de tipo String: USUARIO_REGISTRADO y PASS_REGISTRADA con los valores "admin" y "SentinelPass123" respectivamente.
    3. Pide al usuario que introduzca su nombre de usuario y su contraseña por consola.
    4. Utiliza una estructura if-else para comprobar si ambos, el usuario y la contraseña introducidos, coinciden con las constantes.
      • Si coinciden, muestra el mensaje: "Acceso concedido. Bienvenido a CyberGuard Sentinel."
      • Si no coinciden, muestra: "Acceso denegado. Credenciales incorrectas."
    Aplicación en el Mundo Real:

    Cada sistema que requiere un login, desde una aplicación bancaria hasta una red social, utiliza esta lógica fundamental como primera barrera de seguridad. Hacerlo correctamente es crucial para proteger los datos del usuario.

    2) Módulo de Privilegios: Chequeo de Administrador | Nivel: Fácil

    Objetivo:

    Utilizar una estructura if simple (sin else) para ejecutar una acción adicional solo si se cumple una condición específica.

    Tarea a realizar:
    1. Crea una clase VerificadorPrivilegios.
    2. Dentro del main, declara una variable boolean llamada esAdmin e inicialízala a true (puedes cambiarla a false para probar).
    3. Declara una variable String con el nombreUsuario.
    4. El programa siempre debe imprimir un mensaje de bienvenida general, por ejemplo: "Bienvenido, [nombreUsuario]".
    5. A continuación, usa una estructura if para comprobar si esAdmin es true.
    6. Solo si es administrador, imprime un mensaje adicional: "Panel de administración activado. Tenga cuidado."
    Aplicación en el Mundo Real:

    En las aplicaciones, ciertas funcionalidades (como borrar usuarios o cambiar configuraciones críticas) solo deben ser visibles o accesibles para roles específicos. Un if simple es la forma de implementar esta lógica de "bonus" o acceso especial.

    3) Módulo de Análisis: Clasificador de Amenazas | Nivel: Fácil

    Objetivo:

    Aplicar la estructura if-else if-else para clasificar un valor numérico en diferentes categorías excluyentes.

    Tarea a realizar:
    1. Crea una clase ClasificadorAmenazas.
    2. Pide al usuario que introduzca un "nivel de riesgo" numérico (un entero entre 0 y 100).
    3. Implementa una cadena if-else if-else para mostrar un mensaje según las siguientes reglas:
      • Si el nivel es mayor a 90: "Amenaza Crítica: Acción inmediata requerida."
      • Si el nivel es mayor a 70 (y no es crítico): "Amenaza Alta: Se recomienda supervisión."
      • Si el nivel es mayor a 30 (y no es alto ni crítico): "Amenaza Media: Revisión periódica necesaria."
      • Para cualquier otro caso (30 o menos): "Amenaza Baja: Sistema en parámetros normales."
    4. Asegúrate de manejar el caso de que alguien introduzca un número negativo o mayor que 100 con un if inicial.
    Aplicación en el Mundo Real:

    Los sistemas de monitorización (de redes, de salud de servidores, etc.) usan constantemente esta lógica para convertir datos numéricos brutos (como el uso de CPU o el tráfico de red) en alertas comprensibles y priorizadas para los operadores humanos.

    4) Módulo de Conexión: Selector de Protocolo de Red | Nivel: Fácil

    Objetivo:

    Utilizar una estructura switch para gestionar un menú de opciones basado en un valor entero, demostrando su legibilidad frente a un if-else if largo.

    Tarea a realizar:
    1. Crea una clase SelectorProtocolo.
    2. Muestra al usuario un menú de opciones: 
      Seleccione el protocolo de conexión:
1. HTTP (Navegación web)
2. FTP (Transferencia de archivos)
3. SSH (Acceso remoto seguro)
4. SMTP (Envío de correo)
    3. Pide al usuario que elija una opción (un número del 1 al 4).
    4. Usa una estructura switch sobre la opción elegida.
    5. Para cada case, imprime un mensaje confirmando la selección. Por ejemplo, para el caso 1: "Estableciendo conexión vía HTTP...".
    6. Incluye un caso default para manejar opciones no válidas, mostrando el mensaje "Protocolo desconocido. Conexión cancelada."
    7. Importante: No olvides el break en cada case.
    Aplicación en el Mundo Real:

    Los menús de configuración en aplicaciones de consola, los cajeros automáticos o cualquier sistema que ofrezca al usuario una lista de acciones discretas son candidatos perfectos para ser implementados con un switch.

    5) Depuración: El Bug en el Control de Acceso | Nivel: Fácil

    Objetivo:

    Identificar y corregir un error lógico común en una estructura condicional.

    Setup Inicial:

    Copia el siguiente código en una nueva clase ControlDeAccesoBug. Contiene un error sutil.

    import java.util.Scanner;

public class ControlDeAccesoBug {
    public static void main(String[] args) {
        // Un usuario es VIP si tiene nivel de acceso 5 O si es empleado del mes.
        final int NIVEL_ACCESO_VIP = 5;

        Scanner scanner = new Scanner(System.in);

        System.out.print("Introduce tu nivel de acceso (1-5): ");
        int nivelUsuario = scanner.nextInt();

        System.out.print("¿Eres el empleado del mes? (true/false): ");
        boolean esEmpleadoDelMes = scanner.nextBoolean();

        // ¡Hay un error en la siguiente condición!
        if (nivelUsuario == NIVEL_ACCESO_VIP || esEmpleadoDelMes) {
            System.out.println("Acceso a la zona VIP concedido.");
        } else {
            System.out.println("Acceso a la zona VIP denegado.");
        }

        scanner.close();
    }
}
    Tarea a realizar:
    1. Lee el comentario que describe la regla de negocio: "Un usuario es VIP si tiene nivel de acceso 5 Y si es empleado del mes".
    2. Ejecuta el programa tal como está. Prueba a introducir un nivel de acceso 5 y false para empleado del mes. ¿Qué ocurre? Ahora prueba con nivel 3 y true. ¿El comportamiento es el esperado según la regla?
    3. Identifica el operador lógico incorrecto en la condición del if.
    4. Reemplázalo por el operador correcto para que la lógica cumpla con el requisito.
    5. Vuelve a probar los casos anteriores para verificar que ahora funciona como se espera.
    Aplicación en el Mundo Real:

    Los errores lógicos son de los más comunes y a veces difíciles de detectar, ya que el programa compila y se ejecuta sin fallar. Un simple || en lugar de un && puede crear una brecha de seguridad masiva. La depuración es una habilidad esencial para cualquier programador.

    Ejercicios de Refuerzo

    6) Módulo de Firewall: Reglas de Conexión Anidadas | Nivel: Medio

    Objetivo:

    Implementar condicionales anidados (if dentro de otro if) para simular una regla de firewall que evalúa múltiples criterios secuencialmente.

    Tarea a realizar:
    1. Crea una clase SimuladorFirewall.
    2. Pide al usuario que introduzca una dirección IP de origen (como un String) y un número de puerto (como un int).
    3. Define dos constantes: IP_BLOQUEADA con valor "192.168.1.100" y PUERTO_ADMIN con valor 22.

    4. Implementa la siguiente lógica con if anidados:

      • El if exterior comprobará si la IP introducida NO es igual a la IP_BLOQUEADA.
      • Si la IP no está bloqueada, el if interior comprobará si el puerto es el PUERTO_ADMIN (22).
        • Si es el puerto de admin, mostrará: "Alerta: Intento de acceso al puerto de administración (22) desde una IP permitida. Se requiere monitoreo."
        • Si no es el puerto de admin, mostrará: "Conexión permitida. Tráfico normal."
      • Si la IP SÍ está en la lista de bloqueadas (en el else del primer if), mostrará el mensaje: "Conexión bloqueada. La IP de origen está en la lista negra."

    5. Pista: Recuerda usar .equals() para comparar String y == para comparar int. El if anidado va dentro de la rama "true" del if principal.

    Aplicación en el Mundo Real:

    Los firewalls y los sistemas de control de acceso a redes procesan millones de paquetes por segundo aplicando conjuntos de reglas jerárquicas. La lógica anidada es fundamental para evaluar condiciones en un orden específico, descartando tráfico no deseado lo antes posible.

    7) Módulo de Licencias: Gestor de Características (Switch Expression) | Nivel: Medio

    Objetivo:

    Utilizar una "Switch Expression" de JAVA 12+ para asignar un valor a una variable de forma más concisa y segura, basado en el tipo de licencia de un usuario.

    Tarea a realizar:
    1. Crea una clase GestorLicencias.
    2. Pide al usuario que introduzca su tipo de licencia: "FREE", "PRO" o "ENTERPRISE".
    3. Usa una Switch Expression para determinar las características disponibles y asignarlas a una variable String llamada features.
      • case "FREE" -> "Acceso a funcionalidades básicas."
      • case "PRO" -> "Acceso a funcionalidades básicas y de colaboración."
      • case "ENTERPRISE" -> "Acceso total, incluyendo reportes avanzados y soporte prioritario."
      • default -> "Tipo de licencia no reconocido."

    4. Al final, imprime el valor de la variable features.

    5. Pista: La sintaxis de una Switch Expression es variable = switch (valor) { case "A" -> "Resultado A"; default -> "Resultado por defecto"; };. No olvides el punto y coma al final de toda la expresión.

    Aplicación en el Mundo Real:

    Las aplicaciones SaaS (Software as a Service) gestionan múltiples niveles de suscripción. Usar una Switch Expression permite determinar de forma limpia y segura qué conjunto de permisos o características cargar para un usuario basándose en su nivel de pago, evitando errores de break olvidados.

    8) Módulo de Diagnóstico: Escáner de Vulnerabilidades | Nivel: Medio

    Objetivo:

    Construir una condición if compleja utilizando múltiples operadores lógicos (&&, ||, !) para determinar si un sistema es vulnerable.

    Tarea a realizar:
    1. Crea una clase EscanerVulnerabilidades.
    2. Simula el estado de un sistema con tres variables boolean:
      • sistemaOperativoActualizado
      • antivirusInstalado
      • firewallActivado
    3. Pide al usuario que introduzca el estado de cada una de estas variables (true o false).
    4. La regla de vulnerabilidad es la siguiente: un sistema se considera "ALTAMENTE VULNERABLE" si el sistema operativo NO está actualizado Y (el antivirus NO está instalado O el firewall NO está activado).
    5. Escribe una única sentencia if que implemente esta regla. Si la condición es verdadera, imprime el mensaje de "ALTAMENTE VULNERABLE". En caso contrario, imprime "Sistema con seguridad aceptable."

    6. Prueba varias combinaciones para asegurarte de que la lógica es correcta.

    7. Pista: La clave está en usar paréntesis para agrupar la parte de la condición del OR. La estructura sería if (!condicionA && (!condicionB || !condicionC)).

    Aplicación en el Mundo Real:

    El software de seguridad y auditoría utiliza reglas lógicas complejas para correlacionar diferentes hallazgos. Un solo problema puede ser de bajo riesgo, pero la combinación de varios problemas (un SO antiguo y un firewall desactivado) eleva la criticidad exponencialmente.

    9) Módulo de Alerta: Códigos de Estado del Sistema | Nivel: Medio

    Objetivo:

    Refactorizar una cadena if-else if-else a una estructura switch para mejorar la legibilidad y mantenibilidad del código que maneja un conjunto de códigos de estado discretos.

    Setup Inicial:

    El siguiente código funciona, pero es verboso. Tu tarea es mejorarlo.

    // Código a refactorizar
int codigoEstado = 2; // Simula un código de estado recibido
String mensaje = "";

if (codigoEstado == 0) {
    mensaje = "OK: El sistema funciona correctamente.";
} else if (codigoEstado == 1) {
    mensaje = "WARNING: Espacio en disco bajo.";
} else if (codigoEstado == 2) {
    mensaje = "ERROR: No se puede conectar a la base de datos.";
} else if (codigoEstado == 3) {
    mensaje = "CRITICAL: Falla de seguridad detectada.";
} else {
    mensaje = "FATAL: Código de estado desconocido.";
}
System.out.println(mensaje);
    Tarea a realizar:
    1. Crea una clase MonitorSistema.
    2. Pide al usuario que introduzca un código de estado (un entero).
    3. Reimplementa la lógica del Setup Inicial utilizando una estructura switch tradicional (con case, break y default).
    4. Prueba con diferentes códigos (0, 1, 2, 3, y uno no válido como 5) para verificar que el comportamiento es idéntico al original, pero el código es más limpio.
    Aplicación en el Mundo Real:

    Muchos sistemas y APIs (Interfaces de Programación de Aplicaciones) se comunican mediante códigos numéricos estandarizados (como los códigos de estado HTTP 200, 404, 500). Un switch es la herramienta ideal en el código que recibe estas respuestas para actuar de una forma u otra de manera ordenada.

    Ejercicios de Ampliación

    10) Módulo de Acceso Dinámico: Política de Hora y Rol | Nivel: Alto

    Objetivo:

    Diseñar e implementar un sistema de control de acceso complejo que combine múltiples variables (rol, hora, nivel de seguridad) utilizando una combinación de switch y if-else anidados.

    Tarea a realizar:
    1. Crea una clase ControlAccesoDinamico.
    2. Pide al usuario tres datos:
      • Rol del usuario (String): "ADMIN", "EMPLEADO", "INVITADO".
      • Hora del día (int): Un número entero de 0 a 23.
      • Nivel de seguridad de la sala (int): Un número del 1 al 5.
    3. Implementa la siguiente política de acceso:
      • ADMIN: Tiene acceso siempre (24h) a cualquier sala (nivel 1-5).
      • EMPLEADO:
        • Solo tiene acceso en horario laboral (de 9 a 18, inclusive).
        • Dentro de su horario, solo puede acceder a salas con nivel de seguridad 3 o inferior.
      • INVITADO:
        • Solo tiene acceso en un horario restringido (de 10 a 17, inclusive).
        • Dentro de su horario, solo puede acceder a salas de nivel 1.
    4. Utiliza un switch para la variable rol. Dentro de cada case, utiliza if-else anidados para verificar la hora y el nivel de seguridad.
    5. Imprime un mensaje claro al final: "Acceso Permitido" o "Acceso Denegado", y si es denegado, intenta explicar brevemente por qué (ej: "Fuera de horario laboral", "Nivel de seguridad demasiado alto").
    Peer Review:

    Intercambia tu solución con un compañero. Revisa su código buscando: * Claridad: ¿La estructura de switch y if anidados es fácil de seguir? * Corrección: ¿Implementa todas las reglas de la política de acceso correctamente? Prueba con casos límite (ej: hora 9, 18, 17; nivel 3, 1). * Manejo de Casos: ¿Qué ocurre si se introduce un rol no válido? ¿Y una hora o nivel fuera de rango? Proporciona feedback constructivo.

    Aplicación en el Mundo Real:

    Los sistemas de control de acceso físico (puertas con tarjetas) o lógicos (acceso a servidores) en grandes corporaciones implementan políticas increíblemente granulares como esta. Ser capaz de traducir un conjunto de reglas de negocio complejas en código lógico robusto es una habilidad de alto nivel.

    11) Refactorización: Optimizando el Intérprete de Comandos | Nivel: Alto

    Objetivo:

    Analizar un bloque de código ineficiente basado en if-else if y refactorizarlo a una estructura switch (tradicional o expression), justificando la mejora.

    Setup Inicial (Código a mejorar):

    Imagina un intérprete de comandos de una aplicación. El siguiente código, aunque funcional, es difícil de leer y de extender.

    import java.util.Scanner;

public class InterpreteComandosLegacy {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.print("CMD> ");
        String comando = scanner.nextLine().toLowerCase();

        if (comando.equals("start")) {
            System.out.println("Iniciando servicios...");
        } else if (comando.equals("stop")) {
            System.out.println("Deteniendo todos los servicios.");
        } else if (comando.equals("restart")) {
            System.out.println("Reiniciando. Por favor, espere.");
        } else if (comando.equals("status")) {
            System.out.println("Estado de los servicios: TODOS ACTIVOS.");
        } else if (comando.equals("help")) {
            System.out.println("Comandos disponibles: start, stop, restart, status, help");
        } else {
            System.out.println("Error: Comando '" + comando + "' no reconocido.");
        }
        scanner.close();
    }
}
    Tarea a realizar:
    1. Crea una nueva clase InterpreteComandosModerno.
    2. Reimplementa la lógica del InterpreteComandosLegacy utilizando la estructura switch que consideres más apropiada (tradicional o una switch expression).
    3. Añade un breve comentario en tu código (o prepárate para explicarlo) respondiendo a estas dos preguntas:
      • ¿Por qué un switch es preferible en este escenario específico?
      • ¿Qué ventajas o desventajas tendría usar una switch expression aquí en lugar de un switch tradicional?
    Peer Review:

    Compara tu refactorización con la de un compañero. * ¿Eligió el mismo tipo de switch que tú? * Discutid las justificaciones. ¿Hay algún argumento que no habías considerado? * ¿Cómo manejaríais la adición de 10 nuevos comandos? ¿Qué estructura escala mejor?

    Aplicación en el Mundo Real:

    Refactorizar código es una tarea diaria para un desarrollador. Mejorar la legibilidad y la eficiencia de un código existente es tan importante como escribir código nuevo. Saber cuándo una estructura de control es más apropiada que otra marca la diferencia entre un código mantenible y una pesadilla a largo plazo.

    12) Módulo de Triaje: Asistente de Respuesta a Incidentes | Nivel: Alto

    Objetivo:

    Crear una herramienta interactiva que combine switch y if-else para guiar a un analista de seguridad a través de un proceso de toma de decisiones.

    Tarea a realizar:
    1. Crea una clase AsistenteDeTriaje.
    2. La herramienta debe hacer tres preguntas consecutivas al analista:
      • Pregunta 1: "Tipo de Alerta (MALWARE, INTRUSION, PHISHING):"
      • Pregunta 2: "Nivel de Severidad (1-10):"
      • Pregunta 3: "¿El sistema afectado es crítico para el negocio? (true/false):"
    3. Implementa la lógica para determinar la "Acción Recomendada" basándote en las respuestas. Usa una combinación de switch para el tipo de alerta y if-else para las otras dos variables.
    4. Reglas de decisión:
      • Si el tipo es MALWARE:
        • Si la severidad es > 7 O el sistema es crítico -> "Acción: Aislar el sistema inmediatamente y escalar a Nivel 2."
        • Si no -> "Acción: Ejecutar escáner antivirus y monitorizar."
      • Si el tipo es INTRUSION:
        • Si el sistema es crítico -> "Acción: Bloquear IP de origen, aislar sistema y contactar con el Equipo de Respuesta a Incidentes (IRT)."
        • Si no es crítico, pero la severidad es > 5 -> "Acción: Bloquear IP de origen y analizar logs."
        • Si no -> "Acción: Monitorizar tráfico desde la IP de origen."
      • Si el tipo es PHISHING:
        • "Acción: Eliminar correo de todos los buzones, resetear credenciales del usuario afectado y enviar comunicado de alerta." (Esta acción es siempre la misma independientemente de las otras variables).
    5. Al final, muestra la "Acción Recomendada" al usuario.
    Peer Review:

    Intercambia tu código con un compañero. * Lógica de Negocio: ¿El código implementa correctamente las complejas reglas de decisión? Probad juntos varios escenarios, especialmente los casos límite. * Usabilidad: ¿La interacción con el programa es clara? ¿Se entiende lo que el programa pide en cada paso? * Robustez: ¿Qué pasa si el usuario introduce un tipo de alerta no válido o una severidad de 15? ¿Cómo podría mejorarse el programa para manejar entradas incorrectas?

    Aplicación en el Mundo Real:

    Los "playbooks" de respuesta a incidentes en ciberseguridad son esencialmente árboles de decisión complejos. Automatizar parte de este triaje a través de una herramienta guiada puede acelerar drásticamente el tiempo de respuesta, minimizar errores humanos y asegurar que se sigan los procedimientos correctos durante una crisis.
