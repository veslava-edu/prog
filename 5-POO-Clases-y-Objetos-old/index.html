    Programación Orientada a Objetos en JAVA

    ¡Hola, equipo! Bienvenidos al que probablemente sea el cambio de mentalidad más importante en vuestro viaje como desarrolladores: la Programación Orientada a Objetos (POO). Hasta ahora, en el [TEMA ANTERIOR], hemos manejado estructuras de datos y hemos creado programas que siguen una secuencia de pasos, como una receta de cocina. Funciona, pero... ¿es escalable? ¿Es mantenible?

    Imaginad por un momento que en lugar de programadores, somos los directores de una enorme fábrica de montaje de vehículos. Nuestro antiguo método sería como tener un único manual de instrucciones larguísimo que dice: "Paso 1: coger tornillo A. Paso 2: atornillarlo a la pieza B...". Si quisiéramos construir una moto en lugar de un coche, tendríamos que reescribir el manual casi desde cero. ¡Un auténtico caos!

    La POO nos propone algo radicalmente distinto. En lugar de un manual gigante, diseñamos "planos" para cada componente: un plano para el "Motor", otro para la "Rueda", otro para el "Chasis". Cada plano (que llamaremos Clase) define qué es cada componente (sus atributos, como la cilindrada del motor) y qué sabe hacer (sus métodos, como arrancar() o acelerar()).

    Luego, para construir un coche, simplemente decimos: "necesito una instancia del plano Motor, cuatro del plano Rueda y una del plano Chasis". Cada una de estas "instancias" es un Objeto, una pieza real y funcional que podemos ensamblar. Si ahora queremos una moto, simplemente cogemos un Motor y dos Ruedas. ¡Reutilización al poder!

    Este es el corazón de la POO: modelar el mundo real (o cualquier problema) como un conjunto de objetos que colaboran entre sí. Es la base sobre la que se construyen las aplicaciones y sistemas más complejos que usáis cada día, desde vuestro videojuego favorito hasta la app del banco. ¡Abróchate el cinturón, que despegamos!

    Conceptos Fundamentales: El ADN de la POO

    Antes de empezar a escribir código, tenemos que tener claro el vocabulario. Estos son los cinco conceptos que forman el ADN de la Programación Orientada a Objetos.

    Definición: Clase

    Una Clase es el plano, el molde o la plantilla a partir de la cual se crean los objetos. No es algo tangible, sino una definición abstracta. Define las propiedades (atributos) y los comportamientos (métodos) que tendrán los objetos creados a partir de ella. Por ejemplo, la clase Humano.

    Definición: Objeto

    Un Objeto es una "instancia" de una clase. Es la materialización del plano. Si la clase Humano es el plano, tú, yo, y cada persona somos objetos de esa clase. Cada objeto tiene su propia identidad y su propio estado (sus atributos tendrán valores específicos).

    Definición: Atributo

    Los Atributos (también llamados variables de instancia o propiedades) son las características que definen a un objeto. Son las variables que pertenecen a una clase. Para un objeto de la clase Humano, los atributos podrían ser nombre, edad, altura...

    Definición: Método

    Los Métodos son las acciones o comportamientos que un objeto puede realizar. Son las funciones que pertenecen a una clase. Para un objeto de la clase Humano, los métodos podrían ser hablar(), comer() o cumplirAnios().

    Definición: Instancia

    Instancia es, en la práctica, un sinónimo de objeto. Cuando creas un objeto a partir de una clase, estás "instanciando" esa clase. El proceso de creación se llama instanciación.


    Anatomía de una Clase en Java

    Una clase en Java es el bloque de construcción fundamental. Es donde definimos esos planos que hemos comentado. Su estructura es sencilla pero poderosa.

    [modificador de acceso] class NombreDeLaClase {
    // 1. Atributos (variables de instancia)
    // Definen el estado del objeto

    // 2. Constructores
    // Métodos especiales para crear e inicializar objetos

    // 3. Métodos (funciones)
    // Definen el comportamiento del objeto
}

    1. Atributos: El Estado del Objeto

    Los atributos son variables que definen las características de cualquier objeto de la clase. Cada instancia de la clase tendrá su propia copia de estos atributos, con sus propios valores.

    Buena Práctica: Encapsulación

    Como veremos más adelante, una de las reglas de oro de la POO es la encapsulación. Esto significa que, por norma general, los atributos de una clase siempre deberían ser private. El acceso a ellos se gestionará a través de métodos públicos. ¡Nunca dejes tus datos expuestos!

    2. Métodos: El Comportamiento del Objeto

    Los métodos definen lo que los objetos de la clase pueden hacer. Pueden usarse para modificar el estado del objeto (cambiar el valor de sus atributos) o para realizar acciones.

    Getters y Setters: Puertas de Acceso Controlado

    Para respetar la encapsulación, usamos métodos especiales para acceder y modificar nuestros atributos privados.

    • Getters: Métodos que "obtienen" (get) y devuelven el valor de un atributo. Suelen empezar por get seguido del nombre del atributo en CamelCase.
    • Setters: Métodos que "establecen" (set) un nuevo valor para un atributo. Suelen empezar por set seguido del nombre del atributo en CamelCase y reciben el nuevo valor como parámetro.

    La gran ventaja de los setters es que nos permiten añadir lógica de validación. Por ejemplo, un método setEdad() podría impedir que se asigne un valor negativo.

    Veamos un primer ejemplo completo con una clase Videojuego.

    // google-java-format

/**
 * Representa un videojuego con sus propiedades básicas.
 * Esta clase sigue los principios de encapsulación.
 */
public class Videojuego {
  // Atributos privados para encapsular el estado
  private String titulo;
  private String genero;
  private int jugadores;
  private int puntuacion; // Puntuación de 0 a 100

  // Constructor para inicializar el objeto
  public Videojuego(String titulo, String genero, int jugadores) {
    this.titulo = titulo;
    this.genero = genero;
    this.jugadores = jugadores;
    this.puntuacion = 50; // Una puntuación por defecto
  }

  // --- Getters (Métodos de consulta) ---
  public String getTitulo() {
    return this.titulo;
  }

  public String getGenero() {
    return this.genero;
  }

  public int getJugadores() {
    return this.jugadores;
  }

  public int getPuntuacion() {
    return this.puntuacion;
  }

  // --- Setters (Métodos de modificación) ---

  // No creamos un setTitulo() o setGenero() porque asumimos que no cambian.

  public void setJugadores(int jugadores) {
    if (jugadores > 0) {
      this.jugadores = jugadores;
    }
  }

  /**
   * Modifica la puntuación, asegurando que esté siempre entre 0 y 100.
   * @param puntuacion El nuevo valor de la puntuación.
   */
  public void setPuntuacion(int puntuacion) {
    if (puntuacion >= 0 && puntuacion <= 100) {
      this.puntuacion = puntuacion;
    } else if (puntuacion < 0) {
      this.puntuacion = 0;
    } else {
      this.puntuacion = 100;
    }
  }

  // --- Otros Métodos ---
  public void mostrarInfo() {
    System.out.println("--- Ficha del Videojuego ---");
    System.out.println("Título: " + this.titulo);
    System.out.println("Género: " + this.genero);
    System.out.println("Jugadores: " + this.jugadores);
    System.out.println("Puntuación: " + this.puntuacion + "/100");
  }
}

    Y así lo usaríamos desde otra clase (la que tiene el método main):

    // google-java-format

public class TiendaDeJuegos {
  public static void main(String[] args) {
    // Creamos una instancia (objeto) de la clase Videojuego
    Videojuego eldenRing = new Videojuego("Elden Ring", "Action RPG", 1);

    System.out.println("Puntuación inicial: " + eldenRing.getPuntuacion()); // Salida: 50

    // Le damos una nueva puntuación
    eldenRing.setPuntuacion(98);

    // Intentamos poner una puntuación inválida
    eldenRing.setPuntuacion(150); // No hará nada gracias a la validación

    // Mostramos la información completa
    eldenRing.mostrarInfo();
    /*
     * --- Ficha del Videojuego ---
     * Título: Elden Ring
     * Género: Action RPG
     * Jugadores: 1
     * Puntuación: 98/100
     */
  }
}

    El Origen de los Objetos: Constructores y "this"

    Hemos visto que los objetos se crean, pero... ¿cómo exactamente? El responsable de este "parto" es un método muy especial llamado constructor.

    Constructor

    Es un método especial que se llama automáticamente cuando se crea una instancia de una clase con la palabra clave new. Su misión es inicializar los atributos del objeto, dejándolo en un estado válido y listo para ser usado.

    Un constructor tiene dos reglas sagradas: 1. Debe tener exactamente el mismo nombre que la clase. 2. No tiene tipo de retorno, ni siquiera void.

    Si no escribes ningún constructor en tu clase, Java amablemente te proporciona uno por defecto, vacío y sin parámetros, que inicializa los atributos a sus valores predeterminados (0 para números, false para booleanos, null para objetos). Pero en el 99% de los casos, querrás definir el tuyo.

    Sobrecarga de Constructores: Múltiples Formas de Nacer

    Una clase puede tener varios constructores, siempre que su firma (el número y/o tipo de sus parámetros) sea diferente. Esto se llama sobrecarga y es increíblemente útil. Permite crear objetos de diferentes maneras.

    La Palabra Clave this: "Yo, el Objeto"

    Dentro de una clase, a veces necesitamos hacer referencia al propio objeto con el que estamos trabajando. Para eso existe la palabra clave this. Sus dos usos principales son:

    1. Desambiguar entre atributos y parámetros: Si un parámetro de un constructor o método se llama igual que un atributo de la clase, this.nombreAtributo se refiere al atributo, mientras que nombreAtributo a secas se refiere al parámetro. Es una convención muy extendida y recomendable.
    2. Llamar a otro constructor (Constructor Chaining): Desde un constructor, puedes llamar a otro constructor de la misma clase usando this(...). ¡Ojo! Esta debe ser obligatoriamente la primera línea del constructor.

    Veamos el ejemplo de una clase Usuario que aplica estos conceptos.

    // google-java-format

/**
 * Representa un usuario en un sistema.
 * Demuestra la sobrecarga de constructores y el uso de 'this'.
 */
public class Usuario {
  private String nombreUsuario;
  private String email;
  private String password;
  private boolean estaActivo;

  /**
   * Constructor principal que inicializa todos los datos.
   */
  public Usuario(String nombreUsuario, String email, String password) {
    // Uso de 'this' para desambiguar
    this.nombreUsuario = nombreUsuario;
    this.email = email;
    this.password = password;
    this.estaActivo = true; // Por defecto, un usuario nuevo está activo
  }

  /**
   * Constructor sobrecargado para un registro rápido solo con nombre y contraseña.
   * Llama al constructor principal usando this().
   */
  public Usuario(String nombreUsuario, String password) {
    // Llama al otro constructor, pasando un email por defecto
    this(nombreUsuario, "sin-email@dominio.com", password);
  }

  /**
   * Constructor sin parámetros que crea un usuario "invitado".
   */
  public Usuario() {
    // Llama al segundo constructor
    this("invitado", "password");
    this.estaActivo = false;
  }

  // Getters, setters y otros métodos irían aquí...
  public void mostrarPerfil() {
      System.out.println("Usuario: " + this.nombreUsuario + " (" + (this.estaActivo ? "Activo" : "Inactivo") + ")");
      System.out.println("Email: " + this.email);
  }
}

    Y su uso:

    // google-java-format

public class GestionUsuarios {
    public static void main(String[] args) {
        // Usando el constructor principal
        Usuario admin = new Usuario("admin", "admin@sistema.com", "supersecret");

        // Usando el constructor sobrecargado
        Usuario pepe = new Usuario("pepe123", "qwerty");

        // Usando el constructor sin parámetros
        Usuario invitado = new Usuario();

        admin.mostrarPerfil();
        System.out.println("---");
        pepe.mostrarPerfil();
        System.out.println("---");
        invitado.mostrarPerfil();
    }
}

    Miembros de Clase: El Poder de static

    Hasta ahora, todos los atributos y métodos que hemos visto "pertenecen" a una instancia u objeto particular. Cada coche tiene su propio color, cada usuario su propia contraseña. Pero, ¿y si necesitamos una propiedad o un comportamiento que sea común a toda la clase?

    Para eso, Java nos da la palabra clave static. Un miembro static (ya sea atributo o método) no pertenece a ningún objeto, sino a la clase en su conjunto.

    Analogía de la Fábrica

    Pensemos de nuevo en nuestra fábrica de coches. El color de un coche es un atributo de instancia. Pero el contadorTotalDeCochesFabricados es una propiedad de la fábrica (la clase), no de un coche individual. Este contador sería un atributo static.

    Atributos static (Variables de Clase)

    • Solo existe una única copia de esta variable, compartida por todas las instancias de la clase.
    • Si un objeto modifica un atributo static, el cambio es visible para todos los demás objetos de esa clase.
    • Se pueden acceder usando el nombre de la clase, sin necesidad de crear un objeto: NombreClase.nombreAtributoStatic.

    Métodos static

    • Se invocan sobre la clase, no sobre un objeto: NombreClase.metodoStatic().
    • A menudo son funciones de utilidad que no dependen del estado de un objeto particular. Un ejemplo clásico es la clase Math de Java: Math.random() o Math.sqrt(25) no necesitan que crees un objeto Math para funcionar.
    • Importante: Un método static no puede acceder a atributos o métodos de instancia (los no-estáticos), porque no está asociado a ningún objeto. ¡No puede usar this!

    Vamos a crear una clase OperacionMatematica que use métodos static y una clase Punto que use un atributo static para contar cuántos puntos se han creado.

    Ejemplo 1: Clase de Utilidad static

    // google-java-format

/**
 * Una clase de utilidad que solo contiene métodos estáticos.
 * No tiene sentido crear objetos de esta clase.
 */
public final class Calculadora { // 'final' impide que se herede de ella

  // Hacemos el constructor privado para que nadie pueda instanciarla
  private Calculadora() {}

  public static final double PI = 3.14159265359; // Constante estática

  public static int sumar(int a, int b) {
    return a + b;
  }

  public static double areaCirculo(double radio) {
    return PI * radio * radio;
  }
}

    Uso:

    // google-java-format

public class Main {
  public static void main(String[] args) {
    int suma = Calculadora.sumar(5, 10);
    System.out.println("5 + 10 = " + suma);

    double area = Calculadora.areaCirculo(10);
    System.out.println("Área de círculo de radio 10: " + area);

    // Esto daría un error de compilación porque el constructor es privado
    // Calculadora miCalculadora = new Calculadora(); 
  }
}

    Ejemplo 2: Atributo static como contador

    // google-java-format

public class Punto {
  // Atributo estático para contar las instancias creadas
  private static int contadorPuntos = 0;

  private int x;
  private int y;

  public Punto(int x, int y) {
    this.x = x;
    this.y = y;
    // Cada vez que se llama al constructor, se incrementa el contador
    contadorPuntos++;
  }

  // Método estático para obtener el valor del contador
  public static int getContadorPuntos() {
    return contadorPuntos;
  }
}

    Uso:

    // google-java-format

public class GeometriaApp {
  public static void main(String[] args) {
    System.out.println("Puntos creados al inicio: " + Punto.getContadorPuntos()); // Salida: 0

    Punto p1 = new Punto(10, 20);
    Punto p2 = new Punto(5, 15);

    System.out.println("Puntos creados ahora: " + Punto.getContadorPuntos()); // Salida: 2

    Punto p3 = new Punto(0, 0);

    System.out.println("Puntos creados al final: " + Punto.getContadorPuntos()); // Salida: 3
  }
}

    Aplicación en el Mundo Real

    La POO no es un concepto académico; es el pilar sobre el que se construye el software moderno.

    • Frameworks de Desarrollo Web (Spring, Jakarta EE): En entornos como Spring, toda la aplicación se modela como un conjunto de objetos (llamados Beans o Components) que colaboran. El framework se encarga de "instanciar" y "conectar" estos objetos por ti, un concepto llamado Inversión de Control (IoC). Tú defines los planos (las clases) y el framework construye la casa.
    • Desarrollo de Videojuegos (Unity, LibGDX): En un motor de videojuegos, todo es un objeto: el jugador, los enemigos, las balas, los obstáculos... La clase Enemigo puede tener atributos como vida y velocidad, y métodos como atacar() o recibirDanio(). Luego creas múltiples instancias de Enemigo para poblar el nivel.
    • Aplicaciones Android: Cada pantalla (Activity) de una app Android es una clase. Los botones, campos de texto y otros elementos visuales son objetos de clases predefinidas que tú instancias y configuras.
    • APIs y Librerías: Las APIs que consumes (como la de Google Maps o la de Twitter) te exponen un conjunto de clases (Mapa, Tweet, Usuario) con métodos que puedes llamar para interactuar con su servicio, ocultando toda la complejidad interna (encapsulación).

    En resumen, pensar en términos de objetos, responsabilidades y colaboraciones es la habilidad clave que te permitirá construir sistemas robustos, mantenibles y escalables en cualquier área del desarrollo de software.
