    Ejercicios Prácticos: Programación Modular en Java

    Narrativa del Proyecto: Backend para "WellCorp"

    Bienvenidos al equipo de desarrollo de WellCorp, una nueva plataforma de bienestar corporativo. Nuestra misión es crear una aplicación que permita a los empleados registrar sus actividades físicas, monitorizar su progreso y participar en retos de la empresa.

    Para construir un sistema robusto y escalable, aplicaremos desde el primer día los principios de la programación modular. Vuestra tarea será desarrollar diferentes módulos (métodos en Java) que se encargarán de la lógica de negocio de la plataforma. ¡Manos al código!

    Ejercicios de Consolidación

    1) El Glosario del Desarrollador de WellCorp | Nivel: Fácil

    Objetivo:

    Asegurar la comprensión de los conceptos teóricos fundamentales de la programación modular antes de escribir código.

    Tarea a realizar:

    Responde a las siguientes preguntas como si estuvieras documentando el glosario para un nuevo miembro del equipo de WellCorp.

    1. En nuestra plataforma, necesitamos un módulo que calcule el total de calorías quemadas en una semana y nos dé ese número. ¿Deberíamos implementarlo como una función o un procedimiento? ¿Por qué?
    2. Vamos a crear otro módulo para imprimir un ticket de resumen de actividad en la consola. ¿Será una función o un procedimiento? ¿Qué palabra clave (void o return) define su naturaleza?
    3. Al llamar al método registrarActividad("Juan Pérez", "Running", 60), ¿qué son "Juan Pérez", "Running" y 60? ¿Parámetros o argumentos?
    4. Si dentro de un método calcularMetas, declaramos una variable int metaDiaria = 10000;, ¿podemos acceder a metaDiaria desde el método main? ¿Por qué?
    5. ¿Qué demuestra el Teorema del Programa Estructurado y cuáles son las tres estructuras de control que propone?
    Aplicación en el Mundo Real:

    Utilizar la terminología correcta es crucial en un entorno profesional para comunicarse de manera efectiva con otros desarrolladores, evitar malentendidos y escribir documentación clara.

    VER Solución.
    1. Función. Porque necesita realizar un cálculo y devolver un resultado (el número total de calorías) que probablemente será utilizado en otra parte del programa (por ejemplo, para asignarlo a una variable o mostrarlo en la interfaz).
    2. Procedimiento. Su única tarea es realizar una acción (imprimir en consola) pero no necesita devolver ningún valor. Se define usando la palabra clave void.
    3. Son argumentos. Son los valores reales y concretos que se le pasan al método en el momento de la llamada. Los parámetros son las variables declaradas en la firma del método que reciben estos valores.
    4. No. La variable metaDiaria es local al método calcularMetas. Su ámbito (scope) se limita a ese método. Muere cuando el método termina su ejecución y es inaccesible desde el exterior.
    5. El Teorema del Programa Estructurado demuestra que cualquier algoritmo puede ser implementado usando únicamente tres estructuras de control: Secuencia (una instrucción después de otra), Selección (condicionales como if/switch) e Iteración (bucles como for/while). Esto elimina la necesidad del caótico goto.

    2) Depuración: El Misterio de los Puntos de Bienestar | Nivel: Fácil

    Objetivo:

    Identificar y corregir un error común relacionado con el paso de parámetros por valor en tipos primitivos.

    Setup Inicial:

    En WellCorp, los usuarios ganan puntos por cada actividad. Un desarrollador junior ha intentado crear un método para añadir puntos a un usuario, pero no funciona como esperaba.

    // Código con errores
public class WellnessPoints {

    public static void addBonusPoints(int currentPoints) {
        System.out.println("  -> Método recibe puntos: " + currentPoints);
        currentPoints += 100; // Añade 100 puntos de bonus
        System.out.println("  -> Método modifica los puntos a: " + currentPoints);
    }

    public static void main(String[] args) {
        int userPoints = 500;
        System.out.println("Puntos del usuario ANTES de llamar al método: " + userPoints);
        addBonusPoints(userPoints);
        System.out.println("Puntos del usuario DESPUÉS de llamar al método: " + userPoints);
    }
}
    Tarea a realizar:
    1. Ejecuta el código mentalmente o en un IDE. ¿Cuál es el resultado final impreso en la consola?
    2. Explica por qué userPoints en el main no cambia su valor.
    3. Modifica el método addBonusPoints para que sea una función que devuelva el nuevo total de puntos.
    4. Ajusta la llamada en el main para que capture el valor devuelto y actualice userPoints correctamente.
    Aplicación en el Mundo Real:

    Entender el paso por valor es fundamental en Java. Este error es uno de los más comunes al empezar y saber cómo manejarlo correctamente (por ejemplo, devolviendo el nuevo valor) es una habilidad clave.

    VER Solución.
    1. El resultado final será Puntos del usuario DESPUÉS de llamar al método: 500.

    2. La variable userPoints no cambia porque los tipos primitivos en Java (int en este caso) se pasan por valor. El método addBonusPoints recibe una copia de userPoints, no la variable original. Cualquier cambio se realiza sobre esa copia local, que se destruye al finalizar el método.

    3. y 4. Código Corregido:

    public class WellnessPoints {

    // 3. Convertido a una FUNCIÓN que devuelve el nuevo valor
    public static int addBonusPoints(int currentPoints) {
        System.out.println("  -> Método recibe puntos: " + currentPoints);
        currentPoints += 100; // Añade 100 puntos de bonus
        System.out.println("  -> Método calcula los nuevos puntos: " + currentPoints);
        return currentPoints; // Devuelve el resultado
    }

    public static void main(String[] args) {
        int userPoints = 500;
        System.out.println("Puntos del usuario ANTES de llamar al método: " + userPoints);

        // 4. Se captura el valor devuelto y se reasigna a la variable original
        userPoints = addBonusPoints(userPoints);

        System.out.println("Puntos del usuario DESPUÉS de llamar al método: " + userPoints);
    }
}

    3) Módulo de Registro: Tu Primera Función y Procedimiento | Nivel: Fácil

    Objetivo:

    Crear un método que devuelve un valor (función) y otro que solo realiza una acción (procedimiento) para afianzar la diferencia.

    Tarea a realizar:
    1. Crea una función estática llamada calculateWeeklyScore.
      • Debe recibir un array de enteros (int[]) que representa los pasos diarios de un usuario durante una semana (7 días).
      • Debe calcular la suma total de los pasos de la semana.
      • Debe devolver el total calculado como un int.
    2. Crea un procedimiento estático llamado displayUserProfile.
      • Debe recibir tres String: username, department y un int totalScore.
      • Debe imprimir en consola una ficha de usuario formateada con estos datos.
    3. En el método main, crea un array de pasos, llama a calculateWeeklyScore para obtener el total, y luego llama a displayUserProfile para mostrar la ficha completa.
    Aplicación en el Mundo Real:

    En cualquier aplicación, la lógica se separa constantemente: algunos métodos calculan datos (funciones) mientras que otros los muestran o los guardan (procedimientos). Esta separación de responsabilidades es la base del código limpio.

    VER Solución. 
    public class UserDashboard {

    /**
     * FUNCIÓN: Calcula la suma de pasos de un array y devuelve el total.
     * @param dailySteps Array con los pasos de 7 días.
     * @return La suma total de los pasos.
     */
    public static int calculateWeeklyScore(int[] dailySteps) {
        int total = 0;
        for (int steps : dailySteps) {
            total += steps;
        }
        return total;
    }

    /**
     * PROCEDIMIENTO: Muestra una ficha de usuario en consola. No devuelve nada (void).
     * @param username Nombre del usuario.
     * @param department Departamento del usuario.
     * @param totalScore Puntuación total a mostrar.
     */
    public static void displayUserProfile(String username, String department, int totalScore) {
        System.out.println("===================================");
        System.out.println("      PERFIL DE USUARIO WellCorp   ");
        System.out.println("-----------------------------------");
        System.out.println("Usuario: \t" + username);
        System.out.println("Departamento: \t" + department);
        System.out.println("Puntuación Semanal: " + totalScore + " pasos");
        System.out.println("===================================");
    }

    public static void main(String[] args) {
        // Datos de un usuario de ejemplo
        String user = "Ana García";
        String dept = "Desarrollo";
        int[] weekSteps = {8500, 9200, 10500, 7800, 12000, 6500, 11000};

        // 1. Llamar a la función para obtener el resultado
        int score = calculateWeeklyScore(weekSteps);

        // 2. Llamar al procedimiento para que realice su acción
        displayUserProfile(user, dept, score);
    }
}

    4) Actualización de Perfil: Entendiendo el Paso por Referencia | Nivel: Fácil

    Objetivo:

    Observar cómo la modificación del estado de un objeto dentro de un método afecta a la variable original fuera de él.

    Tarea a realizar:
    1. Crea un método estático y void (procedimiento) llamado promoteUser.
      • Este método debe recibir un array de String como parámetro, que representará los datos de un usuario: userData[0] es el nombre y userData[1] es el rol.
    2. Dentro de promoteUser, modifica el segundo elemento del array (userData[1]) al valor "Team Lead".
    3. En el método main:
      • Crea un array de String llamado employee con los valores {"Carlos Ruiz", "Developer"}.
      • Imprime el rol del empleado antes de llamar a promoteUser.
      • Llama al método promoteUser, pasándole el array employee.
      • Imprime el rol del empleado después de llamar al método.
    4. Analiza el resultado. ¿Por qué cambió el array original en main esta vez?
    Aplicación en el Mundo Real:

    Este comportamiento es la base de cómo se manipulan los objetos en Java. Cuando pasas un objeto a un método (por ejemplo, un objeto User a un método updateEmail), esperas que los cambios realizados dentro del método persistan en el objeto original.

    VER Solución. 

    import java.util.Arrays;

public class UserPromotion {

    /**
     * Modifica el estado del objeto (array) recibido.
     * @param userData Array con los datos del usuario.
     */
    public static void promoteUser(String[] userData) {
        System.out.println("  -> Método recibe el rol: " + userData[1]);
        // Modificamos el contenido del objeto al que apunta la referencia
        userData[1] = "Team Lead";
        System.out.println("  -> Método actualiza el rol a: " + userData[1]);
    }

    public static void main(String[] args) {
        String[] employee = {"Carlos Ruiz", "Developer"};

        System.out.println("Rol ANTES de la promoción: " + employee[1]);

        promoteUser(employee);

        System.out.println("Rol DESPUÉS de la promoción: " + employee[1]);
    }
}
    Análisis del resultado: El array original en main cambia porque en Java, los objetos (y los arrays son objetos) se pasan por copia de la referencia. Esto significa que el método promoteUser no recibe una copia del array en sí, sino una copia de la dirección de memoria donde se encuentra el array original. Tanto employee en main como userData en promoteUser apuntan al mismo objeto en memoria. Por lo tanto, cualquier modificación en el estado interno del objeto a través de una de estas referencias es visible a través de la otra.

    5) Generador de Nombres de Usuario | Nivel: Fácil

    Objetivo:

    Practicar la creación de una función que manipula cadenas de texto (String) y devuelve un nuevo valor.

    Tarea a realizar:
    1. Basándote en el ejemplo generateUsername del material didáctico, crea tu propia versión de una función estática con las siguientes reglas:
      • Nombre del método: createAlias.
      • Recibe dos String: firstName y birthYear.
      • El alias se formará con:
        • Las primeras tres letras del nombre, en mayúsculas.
        • El carácter _.
        • Los dos últimos dígitos del año de nacimiento.
      • Ejemplo: createAlias("Beatriz", "1995") debería devolver "BEA_95".
    2. Añade una validación: si el nombre tiene menos de 3 letras, deberá usar el nombre completo. Ejemplo: createAlias("Ana", "2001") debería devolver "ANA_01".
    3. Llama a la función desde main con al menos dos ejemplos diferentes y muestra el resultado.
    Aplicación en el Mundo Real:

    Generar identificadores únicos, slugs para URLs, o códigos de referencia a partir de otros datos es una tarea extremadamente común en el desarrollo de backends para cualquier tipo de aplicación.

    VER Solución. 
    public class AliasGenerator {

    /**
     * Crea un alias de usuario basado en su nombre y año de nacimiento.
     * @param firstName El nombre del usuario.
     * @param birthYear El año de nacimiento del usuario como String.
     * @return Un alias formateado, por ejemplo, "BEA_95".
     */
    public static String createAlias(String firstName, String birthYear) {
        // Validación por si los datos son nulos o vacíos
        if (firstName == null || birthYear == null || firstName.isEmpty() || birthYear.length() != 4) {
            return "INVALID_DATA";
        }

        String namePart;
        if (firstName.length() < 3) {
            namePart = firstName.toUpperCase();
        } else {
            namePart = firstName.substring(0, 3).toUpperCase();
        }

        String yearPart = birthYear.substring(2); // Obtiene los dos últimos caracteres

        return namePart + "_" + yearPart;
    }

    public static void main(String[] args) {
        String alias1 = createAlias("Beatriz", "1995");
        System.out.println("Alias para Beatriz (1995): " + alias1); // BEA_95

        String alias2 = createAlias("Ana", "2001");
        System.out.println("Alias para Ana (2001): " + alias2); // ANA_01

        String alias3 = createAlias("Leo", "2010");
        System.out.println("Alias para Leo (2010): " + alias3); // LEO_10
    }
}

    6) Registro de Actividad con Sobrecarga | Nivel: Medio

    Objetivo:

    Implementar la sobrecarga de métodos para ofrecer distintas formas de registrar una actividad física, aportando flexibilidad al sistema WellCorp.

    Tarea a realizar:

    Crea una clase ActivityLogger con tres versiones sobrecargadas del método logActivity: 1. logActivity(String user, String activityType): Esta versión solo registra una actividad simple. Debe imprimir un mensaje como "[INFO] - El usuario [user] ha registrado la actividad: [activityType].". 2. logActivity(String user, String activityType, int durationInMinutes): Esta versión añade la duración. Debe imprimir un mensaje como "[INFO] - El usuario [user] ha registrado [activityType] durante [duration] minutos.". 3. logActivity(String user, String activityType, int durationInMinutes, int caloriesBurned): La versión más completa, que también incluye las calorías quemadas. Debe imprimir "[INFO] - El usuario [user] ha completado [activityType] ([duration] min), quemando [calories] kcal.".

    En el main, llama a cada una de las tres versiones para demostrar que Java elige la correcta basándose en los argumentos proporcionados.

    • Pista: Recuerda que la sobrecarga funciona si la lista de parámetros (cantidad o tipo) es diferente entre los métodos con el mismo nombre. El tipo de retorno no influye.
    Aplicación en el Mundo Real:

    La sobrecarga es muy usada en librerías y frameworks para proporcionar "constructores" o métodos que pueden ser llamados de formas más simples o más complejas según la necesidad del desarrollador, mejorando la usabilidad de la API.

    VER Solución. 
    import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;

public class ActivityLogger {

    // Método base para obtener el timestamp, para no repetir código.
    private static String getTimestamp() {
        return LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss"));
    }

    // Versión 1: Actividad simple
    public static void logActivity(String user, String activityType) {
        System.out.println(
            "[" + getTimestamp() + "] [INFO] - El usuario " + user + " ha registrado la actividad: " + activityType + "."
        );
    }

    // Versión 2: Con duración
    public static void logActivity(String user, String activityType, int durationInMinutes) {
        System.out.println(
            "[" + getTimestamp() + "] [INFO] - El usuario " + user + " ha registrado " + activityType + " durante " + durationInMinutes + " minutos."
        );
    }

    // Versión 3: Con duración y calorías
    public static void logActivity(String user, String activityType, int durationInMinutes, int caloriesBurned) {
        System.out.println(
            "[" + getTimestamp() + "] [INFO] - El usuario " + user + " ha completado " + activityType + " (" + durationInMinutes + " min), quemando " + caloriesBurned + " kcal."
        );
    }

    public static void main(String[] args) {
        System.out.println("Registrando actividades en WellCorp...");

        // Llamada a la primera versión
        logActivity("Laura", "Meditación");

        // Llamada a la segunda versión
        logActivity("Marcos", "Running", 45);

        // Llamada a la tercera versión
        logActivity("Elena", "Ciclismo", 90, 650);
    }
}

    7) Módulo de Validación de Datos | Nivel: Medio

    Objetivo:

    Crear un módulo de validación con varios métodos que encapsulen reglas de negocio específicas, promoviendo la reutilización de código.

    Tarea a realizar:

    Crea una clase DataValidator con dos funciones de validación estáticas y públicas: 1. isValidEmail(String email): * Debe devolver true si el email contiene un símbolo @ y un . después del @. * Debe devolver false en cualquier otro caso. * No es necesario usar expresiones regulares complejas, una simple comprobación de la presencia y orden de los caracteres es suficiente. 2. isPasswordSecure(String password): * Debe devolver true solo si la contraseña cumple todas estas condiciones: * Tiene al menos 8 caracteres de longitud. * Contiene al menos un número (puedes hacer un bucle y usar Character.isDigit()). * Debe devolver false si alguna de las condiciones no se cumple. 3. Crea un procedimiento registerUser(String email, String password) que use los dos métodos anteriores. * Si ambos son válidos, debe imprimir "Usuario registrado con éxito." * Si el email es inválido, debe imprimir "Error: El formato del email es incorrecto." * Si la contraseña es insegura, debe imprimir "Error: La contraseña no cumple los requisitos de seguridad." 4. Llama a registerUser desde el main con diferentes datos para probar todos los casos.

    Aplicación en el Mundo Real:

    Tener un módulo centralizado de validación (Validator) es una práctica estándar en el desarrollo de software. Evita duplicar las mismas reglas de validación en múltiples partes de una aplicación, haciendo que el mantenimiento sea mucho más sencillo.

    VER Solución. 
    public class DataValidator {

    /**
     * Valida si un email tiene un formato básico correcto.
     * @param email El email a validar.
     * @return true si es válido, false si no.
     */
    public static boolean isValidEmail(String email) {
        if (email == null || !email.contains("@") || !email.contains(".")) {
            return false;
        }
        // Asegura que el punto esté después de la arroba
        return email.lastIndexOf('.') > email.lastIndexOf('@');
    }

    /**
     * Valida si una contraseña cumple con los requisitos de seguridad.
     * @param password La contraseña a validar.
     * @return true si es segura, false si no.
     */
    public static boolean isPasswordSecure(String password) {
        if (password == null || password.length() < 8) {
            return false;
        }
        boolean hasDigit = false;
        for (char c : password.toCharArray()) {
            if (Character.isDigit(c)) {
                hasDigit = true;
                break; // Si encontramos un dígito, no hace falta seguir
            }
        }
        return hasDigit;
    }

    /**
     * Intenta registrar a un usuario validando sus credenciales.
     * @param email El email del usuario.
     * @param password La contraseña del usuario.
     */
    public static void registerUser(String email, String password) {
        if (!isValidEmail(email)) {
            System.out.println("Error: El formato del email es incorrecto.");
        } else if (!isPasswordSecure(password)) {
            System.out.println("Error: La contraseña no cumple los requisitos de seguridad.");
        } else {
            System.out.println("¡Usuario registrado con éxito!");
        }
    }

    public static void main(String[] args) {
        System.out.println("--- Pruebas de Registro ---");

        // Caso 1: Todo correcto
        System.out.print("Probando con 'test@example.com' y 'password123': ");
        registerUser("test@example.com", "password123");

        // Caso 2: Email inválido
        System.out.print("Probando con 'test.example.com' y 'password123': ");
        registerUser("test.example.com", "password123");

        // Caso 3: Contraseña muy corta
        System.out.print("Probando con 'test@example.com' y 'pass1': ");
        registerUser("test@example.com", "pass1");

        // Caso 4: Contraseña sin números
        System.out.print("Probando con 'test@example.com' y 'password': ");
        registerUser("test@example.com", "password");
    }
}

    8) Cálculo Recursivo de Metas Semanales | Nivel: Medio

    Objetivo:

    Aplicar el concepto de recursividad para resolver un problema que podría resolverse de forma iterativa, con el fin de entender su mecánica.

    Tarea a realizar:

    En WellCorp, se quiere mostrar una proyección de "puntos de consistencia". La idea es que un usuario empiece con 10 puntos el día 1, y cada día subsiguiente gane los puntos del día anterior más un 10% extra (redondeado hacia abajo al entero más cercano).

    1. Crea una función recursiva llamada calculateConsistencyPoints(int day).
    2. Caso Base: Si day es 1, la función debe devolver 10.
    3. Llamada Recursiva: Si day es mayor que 1, la función debe devolver el resultado de calculateConsistencyPoints(day - 1) más el 10% de ese resultado. La fórmula sería: puntos_dia_anterior + (int)(puntos_dia_anterior * 0.1).
    4. En el main, llama a la función para ver los puntos proyectados para el día 7 y muestra el resultado.
    Aplicación en el Mundo Real:

    Aunque este problema específico es más eficiente con un bucle, entender la recursividad es clave para trabajar con estructuras de datos jerárquicas (como árboles de archivos o categorías en un e-commerce) y para comprender algoritmos más avanzados de "divide y vencerás" como Mergesort o Quicksort.

    VER Solución. 
    public class ConsistencyChallenge {

    /**
     * Calcula los puntos de consistencia para un día específico usando recursividad.
     * @param day El día para el cual calcular los puntos (debe ser > 0).
     * @return Los puntos de consistencia calculados.
     */
    public static int calculateConsistencyPoints(int day) {
        // Caso Base: El primer día siempre otorga 10 puntos.
        if (day <= 1) {
            return 10;
        } else {
            // Llamada Recursiva: Pide los puntos del día anterior.
            int previousDayPoints = calculateConsistencyPoints(day - 1);

            // Calcula los nuevos puntos basados en los del día anterior.
            int newPoints = previousDayPoints + (int) (previousDayPoints * 0.1);

            return newPoints;
        }
    }

    public static void main(String[] args) {
        int targetDay = 7;
        int points = calculateConsistencyPoints(targetDay);
        System.out.println("Proyección de puntos de consistencia para el día " + targetDay + ": " + points + " puntos.");

        // Traza para ver la progresión:

        for (int i = 1; i <= targetDay; i++) {

        }
    }
}

    10) Reto de Diseño: Módulo de Estadísticas | Nivel: Alto

    Objetivo:

    Diseñar y construir un módulo cohesivo siguiendo el principio de responsabilidad única, donde cada método realiza una tarea de cálculo específica y bien definida.

    Tarea a realizar:
    1. Crea una clase UserStats que actuará como nuestro módulo de estadísticas.
    2. Dentro de la clase, implementa las siguientes funciones estáticas:
      • calculateAverage(double[] numbers): Recibe un array de double y devuelve la media. Si el array es nulo o está vacío, debe devolver 0.0.
      • findMax(int[] numbers): Recibe un array de int, encuentra el valor máximo y lo devuelve. Si el array es nulo o vacío, debe devolver Integer.MIN_VALUE.
      • normalizeData(int[] dailySteps, int goal): Recibe un array de pasos diarios y una meta. Debe devolver un nuevo array de double donde cada valor representa el porcentaje de la meta alcanzado ese día (ej: si la meta es 10000 y un día se hicieron 8000 pasos, el valor correspondiente en el nuevo array será 80.0).
    3. Escribe un método main que demuestre el uso de todos los métodos de tu módulo UserStats con datos de ejemplo.
    4. Revisión por Pares (Peer Review):
      • Intercambia tu clase UserStats con un compañero.

        • Robustez: ¿Maneja correctamente los casos límite (arrays nulos o vacíos)?
        • Eficiencia: ¿Hay alguna operación innecesaria en los bucles?
      • Proporciona feedback constructivo por escrito (1-2 párrafos).
    Aplicación en el Mundo Real:

    Este ejercicio simula la creación de una "clase de utilidad" (Utility Class), un patrón muy común en el desarrollo profesional. Clases como Math en Java o StringUtils de Apache Commons son ejemplos famosos de módulos que agrupan funcionalidades relacionadas y reutilizables.

    VER Solución. 
    public class UserStats {

    /**
     * Calcula el valor promedio de un array de doubles.
     * @param numbers Array de números.
     * @return El promedio, o 0.0 si el array es nulo o vacío.
     */
    public static double calculateAverage(double[] numbers) {
        if (numbers == null || numbers.length == 0) {
            return 0.0;
        }
        double sum = 0;
        for (double number : numbers) {
            sum += number;
        }
        return sum / numbers.length;
    }

    /**
     * Encuentra el valor máximo en un array de enteros.
     * @param numbers Array de números.
     * @return El valor máximo, o Integer.MIN_VALUE si el array es nulo o vacío.
     */
    public static int findMax(int[] numbers) {
        if (numbers == null || numbers.length == 0) {
            return Integer.MIN_VALUE;
        }
        int max = numbers[0];
        for (int i = 1; i < numbers.length; i++) {
            if (numbers[i] > max) {
                max = numbers[i];
            }
        }
        return max;
    }

    /**
     * Convierte los pasos diarios a un porcentaje de la meta diaria.
     * @param dailySteps Array de pasos diarios.
     * @param goal La meta de pasos.
     * @return Un nuevo array de doubles con los porcentajes.
     */
    public static double[] normalizeData(int[] dailySteps, int goal) {
        if (dailySteps == null || goal <= 0) {
            return new double[0]; // Devuelve un array vacío si los datos son inválidos
        }
        double[] normalized = new double[dailySteps.length];
        for (int i = 0; i < dailySteps.length; i++) {
            normalized[i] = ((double) dailySteps[i] / goal) * 100.0;
        }
        return normalized;
    }

    // Main para demostración
    public static void main(String[] args) {
        System.out.println("--- Demostración del Módulo UserStats ---");

        // Prueba de calculateAverage
        double[] weeklyExpenses = {12.5, 20.0, 8.75, 15.5, 22.0};
        double avgExpense = calculateAverage(weeklyExpenses);
        System.out.printf("Gasto promedio en almuerzos: %.2f€%n", avgExpense);

        // Prueba de findMax
        int[] dailySteps = {8500, 9200, 10500, 7800, 12300, 6500, 11000};
        int maxSteps = findMax(dailySteps);
        System.out.println("Día con más pasos: " + maxSteps + " pasos.");

        // Prueba de normalizeData
        int dailyGoal = 10000;
        double[] goalPercentage = normalizeData(dailySteps, dailyGoal);
        System.out.println("Porcentaje de meta alcanzado cada día:");
        for (int i = 0; i < goalPercentage.length; i++) {
            System.out.printf("  Día %d: %.1f%%%n", (i + 1), goalPercentage[i]);
        }
    }
}

    11) Factorial Recursivo vs. Iterativo: Análisis de Rendimiento | Nivel: Alto

    Objetivo:

    Implementar un algoritmo de dos maneras diferentes (recursiva e iterativa) y analizar las diferencias en términos de claridad del código y (de forma teórica) rendimiento.

    Tarea a realizar:
    1. Crea una clase FactorialCalculator.
    2. Implementa una función recursiva estática factorialRecursive(int n) que calcule el factorial de un número. No olvides el caso base.
    3. Implementa una función iterativa (usando un bucle for o while) estática factorialIterative(int n) que haga exactamente lo mismo.
    4. En el main, calcula el factorial de un número (por ejemplo, 15) usando ambos métodos y comprueba que el resultado es idéntico.
    5. Análisis y Reflexión: Escribe un comentario de bloque (/* ... */) en tu código respondiendo a estas preguntas:
      • ¿Qué versión te parece más fácil de leer y entender a primera vista? ¿Por qué?
      • El factorial de números grandes (ej. 50) causaría un StackOverflowError en la versión recursiva, pero no en la iterativa. Investiga y explica brevemente por qué ocurre esto. ¿Qué es la "pila de llamadas" (call stack)?
    Aplicación en el Mundo Real:

    Saber cuándo usar recursividad (elegante para problemas jerárquicos) y cuándo preferir la iteración (más eficiente en memoria para secuencias lineales) es una marca de un programador maduro. Elegir el enfoque correcto afecta directamente al rendimiento y la mantenibilidad del software.

    VER Solución. 
    public class FactorialCalculator {

    /**
     * Calcula el factorial usando un enfoque recursivo.
     * @param n Número no negativo.
     * @return El factorial de n.
     */
    public static long factorialRecursive(int n) {
        // Validación de entrada
        if (n < 0) return -1; // O lanzar una excepción

        // Caso Base
        if (n == 0) {
            return 1;
        }
        // Llamada Recursiva
        return n * factorialRecursive(n - 1);
    }

    /**
     * Calcula el factorial usando un enfoque iterativo.
     * @param n Número no negativo.
     * @return El factorial de n.
     */
    public static long factorialIterative(int n) {
        // Validación de entrada
        if (n < 0) return -1;

        long result = 1;
        for (int i = 2; i <= n; i++) {
            result *= i;
        }
        return result;
    }

    public static void main(String[] args) {
        int number = 15;

        long recursiveResult = factorialRecursive(number);
        System.out.println("Resultado Recursivo para " + number + "!: " + recursiveResult);

        long iterativeResult = factorialIterative(number);
        System.out.println("Resultado Iterativo para " + number + "!: " + iterativeResult);

        System.out.println("¿Son los resultados iguales? " + (recursiveResult == iterativeResult));
    }

    /*
    Análisis y Reflexión:

    1. ¿Qué versión es más fácil de leer?
    Para muchas personas, la versión recursiva es más elegante y se parece más a la definición
    matemática del factorial (n! = n * (n-1)!). Es muy concisa. Sin embargo, la versión
    iterativa puede ser más intuitiva para quienes están acostumbrados a pensar en términos
    de bucles, ya que muestra el proceso de acumulación de forma más explícita.

    2. ¿Por qué ocurre el StackOverflowError?
    La "pila de llamadas" (call stack) es una estructura de datos que Java utiliza para
    llevar un registro de los métodos que están en ejecución. Cada vez que se llama a un
    método, se añade un "marco" a la pila con la información de ese método (variables locales,
    punto de retorno, etc.).

    En la versión recursiva de `factorial(50)`, la llamada a `factorial(50)` llama a `factorial(49)`,
    que llama a `factorial(48)`, y así sucesivamente. Esto apila 50 marcos de método, uno encima
    del otro, antes de que ninguno de ellos pueda terminar. La pila tiene un tamaño limitado
    y, con números suficientemente grandes, se desborda, causando un `StackOverflowError`.

    La versión iterativa no tiene este problema porque solo hay un marco en la pila para el
    método `factorialIterative`. El bucle se ejecuta dentro de ese único marco, sin hacer
    nuevas llamadas a métodos, por lo que el uso de la memoria de la pila es constante y muy bajo.
    */
