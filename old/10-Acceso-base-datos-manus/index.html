    Acceso a BD Relacionales desde JAVA

    ¡Hola a todos, futuros arquitectos del software! 👋 Bienvenidos a uno de los temas más críticos de vuestra formación en DAW. Si pensabais que vuestros objetos de Java iban a vivir para siempre en la memoria RAM, lamento deciros que la RAM es como la memoria de un pez: en cuanto apagas el servidor, ¡puf!, todo desaparece. 🐟💨

    Para que vuestros datos sobrevivan al apocalipsis de un reinicio de sistema, necesitamos guardarlos en una Base de Datos Relacional. Pero hay un pequeño problema: Java habla en "Objetos" y MySQL habla en "Tablas". Es como intentar que un fan de Star Wars y uno de Star Trek se pongan de acuerdo en cuál es la mejor saga... ¡necesitamos un traductor! Y ese traductor se llama JDBC.

    Analogía Laboral: El Camarero y la Cocina

    Imagina que tu aplicación Java es un cliente en un restaurante y la Base de Datos es la cocina. El cliente no entra a la cocina a freír las patatas (sería un caos de seguridad). En su lugar, usa un camarero (el Driver JDBC) que lleva la comanda (la consulta SQL), se la da al chef (el SGBD), y luego te trae el plato con la comida (el ResultSet). Sin el camarero, ¡te quedarías con hambre y la cocina sería un desastre!

    Conceptos Fundamentales

    Antes de ensuciarnos las manos con código, vamos a dejar claros los términos que usaréis en las entrevistas de trabajo (y para no parecer perdidos en el examen).

    Definición: API (Application Programming Interface)

    Es un conjunto de definiciones y protocolos que permite que dos aplicaciones de software se comuniquen entre sí. Es el "contrato" que dice: "Si me llamas de esta manera, te devolveré este resultado".

    Definición: JDBC (Java Database Connectivity)

    Es una API estándar de Java que permite a las aplicaciones conectarse a casi cualquier base de datos relacional (MySQL, PostgreSQL, Oracle, etc.) usando el mismo conjunto de clases e interfaces. Es el "enchufe universal" de Java para los datos.

    Definición: Driver (Controlador)

    Es la implementación específica para un motor de base de datos concreto. JDBC es la interfaz (el qué), y el Driver es la implementación (el cómo). Sin el driver de MySQL, Java no sabe cómo hablar con MySQL.

    Definición: Desfase Objeto-Relacional

    Es la crisis de identidad que sufren los datos. En Java tenemos clases con herencia y colecciones; en SQL tenemos tablas con filas y columnas. Mapear un objeto Alumno a una fila de la tabla alumnos es lo que conocemos como salvar este desfase.

    Arquitectura JDBC: ¿Cómo se monta el tinglado?

    JDBC no es una sola pieza, es un equipo de componentes trabajando en armonía. Podemos verlo en dos niveles:

    1. Arquitectura de 2 capas (Cliente-Servidor): Tu programa Java habla directamente con la BD. Ideal para aplicaciones pequeñas o herramientas de administración.
    2. Arquitectura de 3 capas: Tu programa Java (en el servidor de aplicaciones) habla con la BD, y el cliente (un navegador) solo ve el resultado. Es el estándar en la web moderna.

    Componentes Clave de JDBC

    Componente Responsabilidad
    DriverManager El "jefe" que gestiona los drivers y establece las conexiones.
    Connection La sesión abierta con la base de datos. ¡No la dejes abierta o el servidor llorará!
    Statement El sobre donde metes tu carta (SQL) para enviarla.
    PreparedStatement Un Statement precompilado. Más rápido y seguro contra inyecciones SQL.
    ResultSet La caja que contiene las filas que te devuelve la base de datos.
    SQLException La clase que maneja cualquier error que ocurra en la base de datos.

    Consejo de Pro

    Antiguamente hacíamos Class.forName("com.mysql.cj.jdbc.Driver") para cargar el driver. En el Java moderno (JDBC 4.0+), esto ya no es estrictamente necesario porque Java es lo suficientemente listo para encontrarlo solo si está en el classpath. ¡Un dolor de cabeza menos!

    Desarrollo y Ejemplos Prácticos

    1. Configuración del Entorno (Maven)

    Olvídate de descargar archivos .jar a mano como si estuviéramos en 2005. Usamos Maven para gestionar las dependencias. En tu pom.xml, añade el conector de MySQL.

    Alerta de Seguridad

    Cuidado con las versiones antiguas de los conectores. A menudo tienen vulnerabilidades (CVEs). Revisa siempre MVNRepository para asegurarte de que no estás usando una versión con "agujeros". Para MySQL 8.4+, usa la versión 9.2.0 del conector.

    Ejemplo 1: Dependencia en pom.xml

    <!-- https://mvnrepository.com/artifact/com.mysql/mysql-connector-j -->
<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <version>9.2.0</version>
</dependency>

    2. Estableciendo la Conexión (Try-with-Resources)

    La forma profesional de manejar conexiones es el try-with-resources (introducido en Java 7). Esto asegura que la conexión se cierre automáticamente incluso si algo explota. Dejar conexiones abiertas es como dejar el grifo abierto: al final, inundas el servidor.

    La URL de conexión sigue este formato: jdbc:subprotocolo://servidor:puerto/base_de_datos

    Ejemplo 2: Conexión básica con Try-with-Resources

    import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionBasica {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        // El bloque try() se encarga de llamar a conn.close() automáticamente
        try (Connection conn = DriverManager.getConnection(url, user, pass)) {
            System.out.println("¡Conexión establecida con éxito! 🚀");
            System.out.println("Catálogo actual: " + conn.getCatalog());
        } catch (SQLException e) {
            System.err.println("Error al conectar: " + e.getMessage());
            System.err.println("Código de estado SQL: " + e.getSQLState());
        }
    }
}

    Ejemplo 3: Conexión con parámetros adicionales en la URL

    A veces necesitas configurar la zona horaria o el uso de SSL directamente en la URL de conexión.

    import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionAvanzada {
    public static void main(String[] args) {
        // Añadimos parámetros para forzar la zona horaria y desactivar SSL (solo para desarrollo local)
        String url = "jdbc:mysql://localhost:3306/gestionalumnos?serverTimezone=UTC&useSSL=false";
        String user = "profesor";
        String pass = "12345678";

        try (Connection conn = DriverManager.getConnection(url, user, pass)) {
            System.out.println("¡Conexión avanzada establecida! 🛠️");
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    3. Consultando Datos (DQL: SELECT)

    Para leer datos usamos Statement y ResultSet. El ResultSet funciona como un cursor que apunta a las filas.

    Detalle Técnico

    El método rs.next() mueve el cursor a la siguiente fila. Al principio, el cursor está antes de la primera fila, por eso siempre hay que llamar a next() al menos una vez. Devuelve true si hay una fila, y false si ya no hay más.

    Ejemplo 4: Consulta básica con Statement

    import java.sql.*;

public class ConsultaAlumnos {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";
        String sql = "SELECT id, nombre, apellido1, ciudad FROM alumno";

        // Anidamos los recursos en el try para que se cierren en orden inverso (rs, stmt, conn)
        try (Connection conn = DriverManager.getConnection(url, user, pass);
             Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {

            System.out.println("--- LISTADO DE ALUMNOS ---");
            while (rs.next()) {
                // Es mejor usar el nombre de la columna que el índice numérico
                int id = rs.getInt("id");
                String nombre = rs.getString("nombre");
                String apellido = rs.getString("apellido1");
                String ciudad = rs.getString("ciudad");

                System.out.printf("[%d] %s %s - %s%n", id, nombre, apellido, ciudad);
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    Ejemplo 5: Consulta con PreparedStatement (La forma correcta)

    Nunca, NUNCA, concatenes Strings para crear una consulta SQL si los datos vienen del usuario. Eso abre la puerta a la Inyección SQL. Usa siempre PreparedStatement.

    import java.sql.*;
import java.util.Scanner;

public class BusquedaSegura {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        // El símbolo '?' es un comodín que rellenaremos después
        String sql = "SELECT * FROM alumno WHERE ciudad = ? AND categoria = ?";

        try (Connection conn = DriverManager.getConnection(url, user, pass);
             PreparedStatement pstmt = conn.prepareStatement(sql);
             Scanner sc = new Scanner(System.in)) {

            System.out.print("Introduce la ciudad a buscar: ");
            String ciudadBuscada = sc.nextLine();

            System.out.print("Introduce la categoría (número): ");
            int categoriaBuscada = sc.nextInt();

            // Sustituimos los comodines (el índice empieza en 1)
            pstmt.setString(1, ciudadBuscada);
            pstmt.setInt(2, categoriaBuscada);

            // Ejecutamos la consulta ya preparada
            try (ResultSet rs = pstmt.executeQuery()) {
                boolean encontrado = false;
                while (rs.next()) {
                    encontrado = true;
                    System.out.println("Encontrado: " + rs.getString("nombre") + " " + rs.getString("apellido1"));
                }
                if (!encontrado) {
                    System.out.println("No hay alumnos en esa ciudad con esa categoría.");
                }
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    4. Modificando Datos (DML: INSERT, UPDATE, DELETE)

    Para cambiar datos, usamos executeUpdate(). Este método devuelve un entero con el número de filas afectadas. Si devuelve 0, ¡algo has hecho mal o no había nada que cambiar!

    Ejemplo 6: Inserción de un nuevo registro

    import java.sql.*;

public class InsertarAlumno {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        String sqlInsert = "INSERT INTO alumno (nombre, apellido1, apellido2, ciudad, categoria) VALUES (?, ?, ?, ?, ?)";

        try (Connection conn = DriverManager.getConnection(url, user, pass);
             PreparedStatement pstmt = conn.prepareStatement(sqlInsert)) {

            pstmt.setString(1, "Brais");
            pstmt.setString(2, "Moure");
            pstmt.setString(3, "Dev");
            pstmt.setString(4, "Galicia");
            pstmt.setInt(5, 1);

            int filasAfectadas = pstmt.executeUpdate();

            if (filasAfectadas > 0) {
                System.out.println("✅ Alumno insertado correctamente. Filas afectadas: " + filasAfectadas);
            } else {
                System.out.println("❌ No se pudo insertar el alumno.");
            }
        } catch (SQLException e) {
            System.err.println("Error en la inserción: " + e.getMessage());
        }
    }
}

    Ejemplo 7: Actualización y Borrado

    import java.sql.*;

public class ModificarBorrar {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        String sqlUpdate = "UPDATE alumno SET ciudad = ? WHERE id = ?";
        String sqlDelete = "DELETE FROM alumno WHERE id = ?";

        try (Connection conn = DriverManager.getConnection(url, user, pass)) {

            // 1. Actualizar
            try (PreparedStatement pstmtUpdate = conn.prepareStatement(sqlUpdate)) {
                pstmtUpdate.setString(1, "Madrid");
                pstmtUpdate.setInt(2, 1); // Suponiendo que el ID 1 existe
                int actualizados = pstmtUpdate.executeUpdate();
                System.out.println("Alumnos actualizados: " + actualizados);
            }

            // 2. Borrar
            try (PreparedStatement pstmtDelete = conn.prepareStatement(sqlDelete)) {
                pstmtDelete.setInt(1, 15); // Borramos al alumno con ID 15
                int borrados = pstmtDelete.executeUpdate();
                System.out.println("Alumnos borrados: " + borrados);
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    5. Metadatos: Preguntándole a la Base de Datos sobre sí misma

    A veces no sabemos qué tablas hay en la base de datos o qué columnas tiene una tabla. Para eso usamos DatabaseMetaData y ResultSetMetaData. Es como pedirle el currículum a la base de datos.

    Ejemplo 8: Obteniendo información de la Base de Datos

    import java.sql.*;

public class ExploradorMetadatos {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        try (Connection conn = DriverManager.getConnection(url, user, pass)) {

            DatabaseMetaData dbmd = conn.getMetaData();

            System.out.println("--- INFO DEL SISTEMA ---");
            System.out.println("SGBD: " + dbmd.getDatabaseProductName());
            System.out.println("Versión SGBD: " + dbmd.getDatabaseProductVersion());
            System.out.println("Driver: " + dbmd.getDriverName());
            System.out.println("Versión Driver: " + dbmd.getDriverVersion());

            System.out.println("\n--- TABLAS EN 'gestionalumnos' ---");
            // Parámetros: catalog, schemaPattern, tableNamePattern, types
            String[] tipos = {"TABLE"};
            try (ResultSet rsTablas = dbmd.getTables("gestionalumnos", null, "%", tipos)) {
                while (rsTablas.next()) {
                    String nombreTabla = rsTablas.getString("TABLE_NAME");
                    System.out.println("Tabla encontrada: " + nombreTabla);
                }
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    6. Transacciones: Asegurando la Integridad de los Datos

    Imagina que estás transfiriendo dinero de una cuenta a otra. Si restas el dinero de la primera cuenta pero la aplicación falla antes de sumarlo a la segunda, ¡tendrías un problema grave! Las transacciones aseguran que un conjunto de operaciones se completen todas juntas (COMMIT) o ninguna (ROLLBACK). Es el "todo o nada" de las bases de datos.

    Por defecto, JDBC opera en modo auto-commit, lo que significa que cada sentencia SQL es una transacción por sí misma. Para gestionar transacciones manualmente, debemos desactivar el auto-commit.

    sequenceDiagram
    participant App as Aplicación Java
    participant DB as Base de Datos

    App->>DB: conn.setAutoCommit(false)
    App->>DB: pstmt1.executeUpdate() (Restar dinero)
    App->>DB: pstmt2.executeUpdate() (Sumar dinero)
    alt Operaciones exitosas
        App->>DB: conn.commit()
        DB-->>App: OK
    else Error en alguna operación
        App->>DB: conn.rollback()
        DB-->>App: OK (Deshace cambios)
    end
    App->>DB: conn.setAutoCommit(true) (Opcional, restaurar)

    Ejemplo 9: Gestión de Transacciones

    import java.sql.*;

public class GestionTransacciones {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";

        Connection conn = null;
        try {
            conn = DriverManager.getConnection(url, user, pass);
            conn.setAutoCommit(false); // Desactivamos el auto-commit

            // Operación 1: Insertar un alumno
            String sqlInsert = "INSERT INTO alumno (nombre, apellido1, ciudad, categoria) VALUES (?, ?, ?, ?)";
            try (PreparedStatement pstmtInsert = conn.prepareStatement(sqlInsert)) {
                pstmtInsert.setString(1, "Laura");
                pstmtInsert.setString(2, "García");
                pstmtInsert.setString(3, "Sevilla");
                pstmtInsert.setInt(4, 2);
                pstmtInsert.executeUpdate();
                System.out.println("Alumno Laura insertado.");
            }

            // Operación 2: Intentar actualizar un alumno que no existe (esto causará un error si no se maneja)
            String sqlUpdate = "UPDATE alumno SET categoria = ? WHERE id = ?";
            try (PreparedStatement pstmtUpdate = conn.prepareStatement(sqlUpdate)) {
                pstmtUpdate.setInt(1, 3);
                pstmtUpdate.setInt(2, 9999); // ID que probablemente no existe
                int filasActualizadas = pstmtUpdate.executeUpdate();
                if (filasActualizadas == 0) {
                    System.out.println("Advertencia: No se actualizó ningún alumno con ID 9999.");
                    // Podríamos lanzar una excepción aquí para forzar el rollback
                    // throw new SQLException("No se encontró el alumno para actualizar.");
                }
            }

            conn.commit(); // Si todo va bien, confirmamos los cambios
            System.out.println("Transacción completada con éxito. Cambios guardados.");

        } catch (SQLException e) {
            System.err.println("Error en la transacción: " + e.getMessage());
            if (conn != null) {
                try {
                    conn.rollback(); // Si algo falla, deshacemos todos los cambios
                    System.out.println("Transacción revertida (rollback).");
                } catch (SQLException ex) {
                    System.err.println("Error al hacer rollback: " + ex.getMessage());
                }
            }
        } finally {
            if (conn != null) {
                try {
                    conn.setAutoCommit(true); // Restaurar auto-commit si es necesario
                    conn.close();
                } catch (SQLException e) {
                    System.err.println("Error al cerrar la conexión: " + e.getMessage());
                }
            }
        }
    }
}

    7. ResultSetMetaData: Conociendo la Estructura de tu Consulta

    ResultSetMetaData te permite obtener información sobre las columnas de un ResultSet, como el nombre de la columna, su tipo de datos, si es autoincremental, etc. Es útil cuando no conoces de antemano la estructura de la tabla o cuando quieres construir una interfaz de usuario dinámica.

    Ejemplo 10: Obteniendo metadatos de un ResultSet

    import java.sql.*;

public class ResultSetMetadataExplorer {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/gestionalumnos";
        String user = "profesor";
        String pass = "12345678";
        String sql = "SELECT id, nombre, apellido1, ciudad FROM alumno";

        try (Connection conn = DriverManager.getConnection(url, user, pass);
             Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {

            ResultSetMetaData rsmd = rs.getMetaData();
            int columnCount = rsmd.getColumnCount();

            System.out.println("--- METADATOS DE LA CONSULTA ---");
            for (int i = 1; i <= columnCount; i++) {
                System.out.printf("Columna %d: %s (Tipo: %s, Etiqueta: %s)%n",
                                  i,
                                  rsmd.getColumnName(i),
                                  rsmd.getColumnTypeName(i),
                                  rsmd.getColumnLabel(i));
            }

            System.out.println("\n--- DATOS ---");
            while (rs.next()) {
                for (int i = 1; i <= columnCount; i++) {
                    System.out.print(rsmd.getColumnLabel(i) + ": " + rs.getObject(i) + "\t");
                }
                System.out.println();
            }

        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    Patrones de Diseño: Singleton y DAO (Implementación Avanzada)

    Como ya vimos, meter todo el código JDBC en el main es una receta para el desastre. Vamos a implementar los patrones Singleton y DAO de forma más robusta y reutilizable.

    8. El Patrón Singleton para la Conexión (Pool de Conexiones)

    Crear una conexión a la base de datos es costoso en tiempo y recursos. El patrón Singleton nos asegura que solo haya una instancia de un objeto, pero para conexiones, lo ideal es un Pool de Conexiones. Un pool mantiene varias conexiones abiertas y listas para usar, lo que mejora drásticamente el rendimiento. Para este ejemplo, simularemos un Singleton simple para la conexión, pero en producción usaríamos librerías como HikariCP o c3p0.

    classDiagram
    class ConexionBD {
        -static Connection instance
        -ConexionBD()
        +static Connection getConnection()
        +static void closeConnection()
    }
    note for ConexionBD "Asegura una única instancia de conexión\n(o simula un pool básico)"

    Ejemplo 11: Implementación del Singleton para la Conexión

    import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;

public class ConexionBD {
    private static Connection instance = null;
    private final static String URL = "jdbc:mysql://localhost:3306/gestionalumnos?serverTimezone=UTC&useSSL=false";
    private final static String USER = "profesor";
    private final static String PASS = "12345678";

    // Constructor privado para evitar instanciación externa
    private ConexionBD() {
        try {
            instance = DriverManager.getConnection(URL, USER, PASS);
            System.out.println("Conexión a la BD establecida (Singleton).");
        } catch (SQLException e) {
            System.err.println("Error al establecer la conexión Singleton: " + e.getMessage());
            e.printStackTrace();
        }
    }

    // Método estático para obtener la única instancia de la conexión
    public static Connection getConnection() {
        if (instance == null) {
            new ConexionBD(); // Crea la instancia si no existe
        }
        return instance;
    }

    // Método para cerrar la conexión (importante en aplicaciones pequeñas)
    public static void closeConnection() {
        if (instance != null) {
            try {
                instance.close();
                System.out.println("Conexión a la BD cerrada (Singleton).");
            } catch (SQLException e) {
                System.err.println("Error al cerrar la conexión Singleton: " + e.getMessage());
            }
        }
    }
}

    Ejemplo 14: Implementación AlumnoDAOImpl

    import java.sql.*;
import java.util.ArrayList;
import java.util.List;

public class AlumnoDAOImpl implements IOperationsCRUD<Alumno, Integer> {

    @Override
    public Alumno save(Alumno alumno) {
        String sql = "INSERT INTO alumno (nombre, apellido1, apellido2, ciudad, categoria) VALUES (?, ?, ?, ?, ?)";
        try (Connection conn = ConexionBD.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {

            pstmt.setString(1, alumno.getNombre());
            pstmt.setString(2, alumno.getApellido1());
            pstmt.setString(3, alumno.getApellido2());
            pstmt.setString(4, alumno.getCiudad());
            pstmt.setInt(5, alumno.getCategoria());

            int affectedRows = pstmt.executeUpdate();
            if (affectedRows > 0) {
                try (ResultSet generatedKeys = pstmt.getGeneratedKeys()) {
                    if (generatedKeys.next()) {
                        alumno.setId(generatedKeys.getInt(1)); // Asignar el ID generado
                    }
                }
            }
            return alumno;
        } catch (SQLException e) {
            e.printStackTrace();
            return null;
        }
    }

    @Override
    public Alumno findById(Integer id) {
        String sql = "SELECT id, nombre, apellido1, apellido2, ciudad, categoria FROM alumno WHERE id = ?";
        try (Connection conn = ConexionBD.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setInt(1, id);
            try (ResultSet rs = pstmt.executeQuery()) {
                if (rs.next()) {
                    return new Alumno(
                        rs.getInt("id"),
                        rs.getString("nombre"),
                        rs.getString("apellido1"),
                        rs.getString("apellido2"),
                        rs.getString("ciudad"),
                        rs.getInt("categoria")
                    );
                }
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
        return null;
    }

    @Override
    public List<Alumno> findAll() {
        List<Alumno> alumnos = new ArrayList<>();
        String sql = "SELECT id, nombre, apellido1, apellido2, ciudad, categoria FROM alumno";
        try (Connection conn = ConexionBD.getConnection();
             Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {

            while (rs.next()) {
                alumnos.add(new Alumno(
                    rs.getInt("id"),
                    rs.getString("nombre"),
                    rs.getString("apellido1"),
                    rs.getString("apellido2"),
                    rs.getString("ciudad"),
                    rs.getInt("categoria")
                ));
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
        return alumnos;
    }

    @Override
    public Alumno update(Alumno alumno) {
        String sql = "UPDATE alumno SET nombre = ?, apellido1 = ?, apellido2 = ?, ciudad = ?, categoria = ? WHERE id = ?";
        try (Connection conn = ConexionBD.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setString(1, alumno.getNombre());
            pstmt.setString(2, alumno.getApellido1());
            pstmt.setString(3, alumno.getApellido2());
            pstmt.setString(4, alumno.getCiudad());
            pstmt.setInt(5, alumno.getCategoria());
            pstmt.setInt(6, alumno.getId());

            int affectedRows = pstmt.executeUpdate();
            return (affectedRows > 0) ? alumno : null;
        } catch (SQLException e) {
            e.printStackTrace();
            return null;
        }
    }

    @Override
    public void delete(Integer id) {
        String sql = "DELETE FROM alumno WHERE id = ?";
        try (Connection conn = ConexionBD.getConnection();
             PreparedStatement pstmt = conn.prepareStatement(sql)) {

            pstmt.setInt(1, id);
            pstmt.executeUpdate();
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

    Ejemplo 16: Uso del DAO en la aplicación principal

    import java.util.List;

public class MainApp {
    public static void main(String[] args) {
        // Obtener la instancia del DAO a través de la factoría
        AlumnoDAO alumnoDAO = FactoriaDAO.getAlumnoDAO();

        // 1. Insertar un nuevo alumno
        Alumno nuevoAlumno = new Alumno("Ana", "Pérez", "López", "Barcelona", 1);
        alumnoDAO.save(nuevoAlumno);
        System.out.println("Alumno insertado: " + nuevoAlumno);

        // 2. Buscar un alumno por ID
        Alumno alumnoEncontrado = alumnoDAO.findById(nuevoAlumno.getId());
        System.out.println("Alumno encontrado: " + alumnoEncontrado);

        // 3. Actualizar un alumno
        if (alumnoEncontrado != null) {
            alumnoEncontrado.setCiudad("Valencia");
            alumnoDAO.update(alumnoEncontrado);
            System.out.println("Alumno actualizado: " + alumnoEncontrado);
        }

        // 4. Listar todos los alumnos
        List<Alumno> todosLosAlumnos = alumnoDAO.findAll();
        System.out.println("\n--- TODOS LOS ALUMNOS ---");
        todosLosAlumnos.forEach(System.out::println);

        // 5. Eliminar un alumno
        if (nuevoAlumno.getId() != 0) { // Asegurarse de que tiene un ID válido
            alumnoDAO.delete(nuevoAlumno.getId());
            System.out.println("Alumno con ID " + nuevoAlumno.getId() + " eliminado.");
        }

        // Cerrar la conexión al finalizar la aplicación (si se usa Singleton simple)
        ConexionBD.closeConnection();
    }
}

    Aplicación en el Mundo Real

    En el mundo profesional, rara vez usarás JDBC directamente para todas las operaciones CRUD. Frameworks como Hibernate o Spring Data JPA construyen una capa de abstracción sobre JDBC, permitiéndote trabajar con objetos Java directamente sin escribir SQL. Sin embargo, entender JDBC es fundamental para:

    • Depuración: Cuando algo falla en Hibernate, saber JDBC te permite entender qué SQL se está ejecutando realmente.
    • Optimización: Para consultas muy complejas o de alto rendimiento, a veces es necesario "bajar" a JDBC puro para un control más fino.
    • Proyectos Legacy: Mantener o migrar aplicaciones antiguas que usan JDBC directamente.
    • Herramientas: Desarrollar herramientas de administración de bases de datos o utilidades específicas.
