    9 - Gestión de Ficheros y Persistencia

    ¡Bienvenidos, futuros arquitectos del software! 👋

    Hasta ahora, vuestros programas padecían de una enfermedad terrible: amnesia anterógrada. Todo lo que calculaban, todos los objetos que creaban y todos los datos que el usuario introducía vivían felices en la memoria RAM... hasta que apagabais el programa. En ese momento, poof, todo desaparecía como lágrimas en la lluvia.

    Hoy vamos a darle a vuestras aplicaciones memoria a largo plazo. Vamos a aprender a persistir la información.

    Imaginad que la RAM es una pizarra en un aula: es rapidísima para escribir y borrar, ideal para trabajar en el momento, pero el conserje (el Sistema Operativo) la borra cada noche. El Disco Duro (Ficheros) es el archivo de la biblioteca: es más lento ir a buscar un libro o guardarlo, pero la información sobrevive años, terremotos y reinicios.

    En este tema, aprenderemos a mover cajas de datos desde la pizarra al archivo y viceversa. ¡Empecemos!

    Conceptos Fundamentales

    Antes de mancharnos las manos de código, definamos las herramientas con las que vamos a trabajar.

    Definición: Fichero (File)

    Es una secuencia de bytes almacenada en un dispositivo de almacenamiento secundario (disco duro, SSD, USB...). Para el sistema operativo, es una unidad lógica que agrupa datos relacionados y tiene un nombre y una ruta (path).

    Definición: Stream (Flujo)

    Es una abstracción que representa una fuente o un destino de datos secuenciales. Imaginadlo como una tubería o una cinta transportadora. Los datos entran por un lado y salen por el otro. No necesitamos tener todo el océano en la tubería, solo el agua que fluye en ese instante.

    Definición: Buffer

    Es una zona de memoria intermedia (como un cubo) que se usa para almacenar datos temporalmente mientras se mueven de un lugar a otro. Usar un buffer reduce el número de viajes al disco duro (que son "caros" en tiempo), mejorando drásticamente el rendimiento.

    Desarrollo y Ejemplos Prácticos

    1. Introducción a los Ficheros

    1.1 ¿Qué es un fichero?

    En el nivel más bajo, un fichero no es más que una colección de ceros y unos. Sin embargo, cómo interpretamos esos bits cambia totalmente la película.

    1.2 Tipos de ficheros: texto y binarios

    Aunque todos son bytes, los dividimos en dos categorías según su interpretación:

    Característica Ficheros de Texto Ficheros Binarios
    Contenido Caracteres legibles (ASCII, UTF-8). Bytes crudos (imágenes, audio, clases compiladas).
    Legibilidad Legibles por humanos (se abren con el Bloc de Notas). Ilegibles directamente (parecen "basura" en un editor de texto).
    Interpretación Se interpretan línea a línea o carácter a carácter. Requieren un software específico que conozca la estructura.
    Ejemplos .txt, .java, .xml, .json, .html .jpg, .mp3, .class, .exe, .zip

    1.3 Flujos (Streams) de entrada y salida

    En Java, la comunicación con el exterior se basa en Streams.
    * Input Stream (Entrada): Tubería para LEER. Los datos vienen hacia tu programa (teclado, fichero, red).
    * Output Stream (Salida): Tubería para ESCRIBIR. Los datos salen desde tu programa.

    graph LR
    A[Fichero en Disco] -->|Input Stream| B(Tu Programa Java)
    B -->|Output Stream| C[Fichero / Consola / Red]

    1.4 Entrada/Salida estándar

    Ya las conocéis, son viejas amigas:
    * System.in: Flujo de entrada estándar (normalmente el teclado). Es un InputStream.
    * System.out: Flujo de salida estándar (la consola). Es un PrintStream.
    * System.err: Flujo de error (consola, pero usualmente en rojo o separado).

    1.5 Uso de try-catch con recursos (try-with-resources)

    La Regla de Oro de los Ficheros

    SIEMPRE debes cerrar un fichero después de usarlo. Dejar un fichero abierto es como dejarte el grifo abierto: desperdicias recursos del sistema y puedes bloquear el archivo para otros programas.

    Antiguamente (Java 6 y anterior) era un dolor de cabeza cerrar ficheros en el bloque finally. Desde Java 7, tenemos el try-with-resources. Cualquier objeto que implemente AutoCloseable se cerrará automáticamente al terminar el bloque try.

    Ejemplo Clásico (Mala práctica hoy en día): 

    // NO HAGÁIS ESTO EN CASA
FileReader fr = null;
try {
    fr = new FileReader("miFichero.txt");
    // leer...
} catch (IOException e) {
    e.printStackTrace();
} finally {
    try {
        if (fr != null) fr.close(); // ¡Qué dolor de código!
    } catch (IOException ex) {
        ex.printStackTrace();
    }
}

    Ejemplo Moderno (Buena práctica): 

    // ESTO SÍ: Limpio, seguro y automático
try (FileReader fr = new FileReader("miFichero.txt")) {
    // Usar el recurso
    int valor = fr.read();
    System.out.println("Leído: " + valor);
} catch (IOException e) {
    System.err.println("Error al acceder al fichero: " + e.getMessage());
}
// Aquí 'fr' ya está cerrado automáticamente, pase lo que pase.

    Ejercicio Reflexivo

    1. Si un fichero binario es más eficiente y ocupa menos espacio, ¿por qué usamos tanto JSON o XML (texto) en la industria hoy en día?
    2. ¿Qué ocurriría si intentamos abrir un fichero para escribir en él, pero no tenemos permisos de administrador en esa carpeta?


    2. Ficheros y Directorios en Java

    Java tiene dos APIs principales para ficheros: la clásica (java.io.File) y la moderna "NIO.2" (java.nio.file). En FP Superior nos enfocamos en la moderna (NIO), pero debéis conocer la clásica porque hay mucho código antiguo por ahí (legacy).

    2.1 Clase File (Legacy)

    Representa una ruta abstracta. No es el contenido, es la dirección. 

    import java.io.File;

File f = new File("documentos/notas.txt");
if (f.exists()) {
    System.out.println("Nombre: " + f.getName());
    System.out.println("Tamaño: " + f.length() + " bytes");
}

    2.2 Clase Path (Moderna)

    Es la versión mejorada de File. Pertenece al paquete java.nio.file. Es inmutable y más versátil para manejar rutas de diferentes sistemas operativos.

    2.3 Clase Paths

    Es una fábrica de objetos Path. 

    import java.nio.file.Path;
import java.nio.file.Paths;

// Crear un Path
Path ruta = Paths.get("data", "usuarios", "lista.txt"); // data/usuarios/lista.txt
System.out.println("Ruta absoluta: " + ruta.toAbsolutePath());

    2.4 Clase Files (La Navaja Suiza)

    Esta clase estática contiene todos los métodos útiles para operar con ficheros usando Path. Es vuestra mejor amiga.

    2.5 Operaciones básicas con ficheros y directorios

    Ejemplo 1: Verificar existencia y crear directorio 

    import java.nio.file.*;
import java.io.IOException;

public class GestionFicheros {
    public static void main(String[] args) {
        Path directorio = Paths.get("mis_datos");
        Path fichero = directorio.resolve("secreto.txt"); // mis_datos/secreto.txt

        try {
            // 1. Crear directorio si no existe
            if (Files.notExists(directorio)) {
                Files.createDirectory(directorio);
                System.out.println("Directorio creado.");
            }

            // 2. Crear fichero vacío
            if (Files.notExists(fichero)) {
                Files.createFile(fichero);
                System.out.println("Fichero creado.");
            }

            // 3. Copiar fichero
            Path copia = directorio.resolve("secreto_backup.txt");
            Files.copy(fichero, copia, StandardCopyOption.REPLACE_EXISTING);
            System.out.println("Backup realizado.");

        } catch (IOException e) {
            e.printStackTrace();
        }
    }
}

    Ejemplo 2: Mover y Borrar 

    try {
    Path origen = Paths.get("mis_datos/secreto.txt");
    Path destino = Paths.get("mis_datos/archivos_viejos/secreto_old.txt");

    // Aseguramos que el directorio destino exista
    Files.createDirectories(destino.getParent());

    // Mover (Renombrar)
    Files.move(origen, destino, StandardCopyOption.REPLACE_EXISTING);

    // Borrar
    // Files.delete(destino); // Lanza excepción si no existe
    boolean borrado = Files.deleteIfExists(destino); // Más seguro

} catch (IOException e) {
    System.err.println("Error en operación de E/S: " + e.getMessage());
}

    2.6 Directorio resources

    En proyectos Java (Maven/Gradle), tenemos una carpeta src/main/resources. Los ficheros aquí se empaquetan dentro del JAR final. No se accede a ellos como ficheros normales, sino como streams del Classpath.

    Alerta: Resources

    No intentes escribir en un fichero dentro de resources en tiempo de ejecución. Esos ficheros son de solo lectura una vez compilada la aplicación.

    2.7 Ficheros temporales

    Útil para datos de usar y tirar. 

    Path tempFile = Files.createTempFile("miAppLog_", ".tmp");
System.out.println("Fichero temporal: " + tempFile);
// Al salir, intentar borrar
tempFile.toFile().deleteOnExit();

    2.8 Ficheros comprimidos (ZIP)

    Java permite tratar un ZIP como si fuera un sistema de ficheros. Es potente pero avanzado. Para uso básico, usamos ZipInputStream y ZipOutputStream.

    Sabías que...

    Los archivos .jar de Java son en realidad archivos .zip con una estructura de carpetas específica (META-INF). Puedes cambiarles la extensión y abrirlos con WinRAR.

    3.1 Clases base

    • InputStream / OutputStream: La madre de los bytes.
    • Reader / Writer: La madre de los caracteres.

    3.2 Streams de bytes (Para imágenes, PDF, etc.)

    Usamos FileInputStream y FileOutputStream. Leen byte a byte (0-255).

    3.3 Streams de caracteres (Para texto)

    Usan Reader y Writer. Gestionan automáticamente la codificación (UTF-8, ISO-8859-1). * InputStreamReader / OutputStreamWriter: Son los puentes. Convierten un flujo de bytes en un flujo de caracteres.

    3.4 Streams con buffer (La clave del rendimiento)

    No leas byte a byte en disco

    Leer un fichero byte a byte directamente del disco es lentísimo. Es como ir al supermercado a comprar un solo huevo, volver a casa, y volver al súper a por otro huevo. Solución: Usa Buffered.... Es como llevar un carro de la compra. Lees un bloque grande de golpe (el buffer) en memoria y vas cogiendo de ahí.

    3.5 PrintWriter

    Es el rey de la escritura de texto cómoda. Tiene los métodos print y println que ya amáis de System.out.

    Ejemplo de combinación de flujos (El patrón Decorator): 

    // Escribir texto eficientemente
try (PrintWriter out = new PrintWriter(
                         new BufferedWriter(
                           new FileWriter("salida.txt")))) {
    out.println("Hola Mundo");
    out.printf("Tengo %d años y aprendo %s", 25, "Java");
} catch (IOException e) { ... }

    3.3.6 Scanner para lectura

    El Scanner no es solo para el teclado. Puede parsear ficheros de texto buscando enteros, líneas, etc.

    3.3.7 Flujos especiales

    • DataInput/Output: Para escribir primitivos (int, boolean, double) en binario de forma portable.
    • Piped...: Para comunicar dos hilos (threads).


    4. Ficheros de Texto

    El 90% de vuestro trabajo será con texto (logs, configuraciones, CSV).

    4.1 y 4.2 Lectura línea a línea (Dos métodos)

    Método A: BufferedReader (Clásico y eficiente) 

    Path ruta = Paths.get("quijote.txt");
try (BufferedReader br = Files.newBufferedReader(ruta)) {
    String linea;
    while ((linea = br.readLine()) != null) {
        System.out.println(linea);
    }
} catch (IOException e) { ... }

    Método B: Files.lines (Java 8+ Streams) Ideal para procesamiento funcional. 

    Path ruta = Paths.get("quijote.txt");
try (Stream<String> lineas = Files.lines(ruta)) {
    lineas.filter(l -> l.contains("Sancho"))
          .map(String::toUpperCase)
          .forEach(System.out::println);
} catch (IOException e) { ... }

    4.4.3 Escritura de ficheros de texto

    List<String> listaCompra = Arrays.asList("Pan", "Huevos", "Leche");
Path destino = Paths.get("lista.txt");

try {
    // Escribe todo de golpe (bueno para ficheros pequeños)
    Files.write(destino, listaCompra, StandardCharsets.UTF_8); 

    // Añadir al final (Append)
    Files.write(destino, Arrays.asList("Cerveza"), 
                StandardOpenOption.APPEND);
} catch (IOException e) { ... }

    4.4.4 Buenas prácticas

    1. Especificar siempre el Charset (UTF-8). No dependáis del defecto del sistema (Windows usa CP1252 y rompe las tildes en Linux).
    2. Usar Buffers para ficheros grandes.
    3. Validar rutas antes de escribir.


    5.5 Ficheros Binarios

    5.5.1 Concepto

    Guardamos la información tal cual está en memoria. Un entero 123456 ocupa 4 bytes en binario, pero 6 bytes en texto ("123456").

    5.5.2 y 5.5.3 Lectura y Escritura (Copiar una imagen)

    Path origen = Paths.get("foto.jpg");
Path destino = Paths.get("copia_foto.jpg");

try (InputStream in = new FileInputStream(origen.toFile());
     OutputStream out = new FileOutputStream(destino.toFile())) {

    byte[] buffer = new byte[1024]; // Buffer de 1KB
    int bytesLeidos;

    // Leemos del origen al buffer y escribimos al destino
    while ((bytesLeidos = in.read(buffer)) != -1) {
        out.write(buffer, 0, bytesLeidos);
    }
    System.out.println("Imagen copiada.");

} catch (IOException e) { ... }


    5.6 Ficheros de Acceso Aleatorio

    5.6.1 ¿Qué es?

    Los flujos normales son secuenciales (como una cinta de casete). El acceso aleatorio (RandomAccessFile) es como un vinilo o un disco duro: puedes saltar inmediatamente al byte 1.000.000 sin leer los anteriores.

    5.6.2 Clase RandomAccessFile

    Tiene un puntero de fichero que podemos mover. * Modos: "r" (lectura), "rw" (lectura/escritura).

    5.6.3 y 5.6.4 Lectura y Escritura

    try (RandomAccessFile raf = new RandomAccessFile("datos.bin", "rw")) {
    // Escribir algo
    raf.writeInt(100); // 4 bytes
    raf.writeDouble(3.14); // 8 bytes

    // Volver al principio (seek)
    raf.seek(0);
    System.out.println(raf.readInt()); // Imprime 100

    // Saltar el double e ir al final
    raf.seek(raf.length());
    raf.writeBoolean(true); // Añadir al final

} catch (IOException e) { ... }


    5.7 Serialización de Objetos

    Es como teletransportar objetos de Star Trek. Desintegramos el objeto en bytes, lo mandamos por la red o a disco, y lo reconstruimos en otro lado.

    5.7.1 y 5.7.2 Concepto e Interfaz

    La clase debe implementar Serializable. 

    import java.io.Serializable;

// DTO simple
public class Usuario implements Serializable {
    private static final long serialVersionUID = 1L; // Importante para versiones
    private String nombre;
    private transient String password; // transient = NO se serializa

    // Constructor, getters, setters...
}

    5.7.3 a 5.7.5 Lectura y Escritura

    Usuario u = new Usuario("Pepe", "1234");

// Serializar (Guardar)
try (ObjectOutputStream oos = new ObjectOutputStream(
        new FileOutputStream("usuario.ser"))) {
    oos.writeObject(u);
}

// Deserializar (Recuperar)
try (ObjectInputStream ois = new ObjectInputStream(
        new FileInputStream("usuario.ser"))) {
    Usuario recuperado = (Usuario) ois.readObject();
    System.out.println("Nombre: " + recuperado.getNombre());
    // password será null porque es transient
}

    Peligro de la Serialización

    La serialización nativa de Java es lenta, produce ficheros grandes y tiene problemas de seguridad. En el mundo moderno, preferimos serializar a JSON para intercambiar datos. Usad la nativa solo para almacenamiento interno temporal simple.


    5.8 Formatos de Intercambio de Datos

    Aquí es donde conectaréis con el mundo real (APIs, Front-ends).

    5.8.1 DTO (Data Transfer Object)

    Es un objeto "tonto" (solo atributos, getters y setters) usado para transportar datos.

    5.8.2 Ficheros properties

    Clave-valor. Típico para configuraciones (config.properties). 

    db.user=admin
db.port=3306
version=1.0
    Java tiene la clase Properties para manejarlos fácilmente.

    5.8.3 CSV (Comma Separated Values)

    Excel para programadores. id,nombre,edad 1,Pepe,25 Se puede parsear a mano con String.split(",") o usando librerías como OpenCSV.

    5.8.4 JSON (JavaScript Object Notation)

    El estándar de facto para la web. 

    {
  "id": 1,
  "nombre": "Pepe",
  "habilidades": ["Java", "SQL"]
}
    En Java, usamos librerías externas porque la nativa es limitada. Las reinas son Jackson y Gson.

    Ejemplo con Gson (necesita librería externa): 

    Gson gson = new Gson();
// Objeto a JSON
String json = gson.toJson(miUsuario);
// JSON a Objeto
Usuario user = gson.fromJson(json, Usuario.class);

    5.8.5 XML

    Estructura de árbol con etiquetas. Verborreico pero robusto. Java tiene JAXB o DOM/SAX para procesarlo. Hoy en día se usa menos que JSON, pero sigue vivo en configuraciones (Maven pom.xml) y sistemas antiguos.


    10. Resumen y Buenas Prácticas

    10.1 Tabla de Decisión

    Escenario Usa...
    Configuración simple .properties
    Intercambio datos web .json
    Tabla de datos / Excel .csv
    Imagen / Audio Binario (FileInputStream)
    Texto grande BufferedReader
    Escribir reporte PrintWriter

    10.2 Gestión correcta de recursos

    • Usa siempre try-with-resources.
    • Usa buffers.

    10.3 Errores comunes

    • Olvidar cerrar el stream (memory leaks).
    • No controlar FileNotFoundException.
    • Usar rutas absolutas ("C:\Users\Yo\...") en lugar de relativas o System.getProperty("user.home"). El código debe funcionar en el PC de tu compañero también.

    Aplicación en el Mundo Real

    1. Logs de Servidores: Cuando una aplicación web falla, escribe el error en un fichero .log usando streams. Herramientas como Splunk o ELK leen esos ficheros masivamente.
    2. Videojuegos: El "Guardar Partida" es pura serialización (a binario o JSON) del estado de los objetos (posición del jugador, inventario, vida).
    3. Bases de Datos: Por debajo, Oracle o MySQL no son magia. Son programas muy sofisticados que escriben y leen ficheros binarios en el disco duro usando acceso aleatorio (RandomAccessFile con esteroides) para ser ultra-rápidos.
