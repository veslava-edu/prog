    7.1 Programación funcional y Streams en Java 21

    Piensa en tu aplicación como si fuera una cinta transportadora de paquetes en Amazon: antes ibas paquete a paquete con una carretilla (bucle for clásico); ahora defines “filtros”, “transformaciones” y “contadores” y dejas que la cinta (los Streams) haga el trabajo por ti de forma declarativa y optimizada. En el mundo real (microservicios, backends con Spring, procesamiento de datos, etc.) este enfoque es clave para escribir código más limpio, mantenible y preparado para CPUs con muchos núcleos.^1^3

    Como ya habéis trabajado estructuras dinámicas de datos (listas, colas, mapas, etc.), ahora vais a ver cómo exprimirlas con programación funcional y Streams en Java 21 para que dejen de ser “sólo contenedores” y pasen a ser auténticas tuberías de procesamiento.^4

    Conceptos fundamentales

    Definición: Programación funcional

    Paradigma donde el foco está en qué se quiere calcular usando funciones puras y combinándolas, evitando estados mutables y efectos secundarios innecesarios.^4

    Definición: Expresión lambda

    Bloque de código anónimo que se puede tratar como dato: se pasa como parámetro, se almacena en variables y se ejecuta más tarde.^5

    Definición: Interfaz funcional

    Interfaz con un único método abstracto (SAM: Single Abstract Method) que se puede implementar con una expresión lambda, como `Predicate<T>`, `Function<T,R>`, `Consumer<T>` o `Supplier<T>` en `java.util.function`.[^6][^5]

    Definición: Stream

    Secuencia perezosa de elementos que permite definir un “pipeline” de operaciones intermedias (map, filter, sorted, …) y una operación terminal (count, collect, reduce, …), sin modificar la colección original.^2

    Definición: Collector

    Objeto que sabe cómo acumular elementos de un Stream en una estructura o resultado (lista, mapa, estadísticas, agrupaciones…). La clase Collectors de Java 21 aporta muchos factory methods como toList(), groupingBy() o partitioningBy().^7

    Definición: Optional

    Contenedor que representa “valor presente” o “ausente” sin usar null, con operaciones funcionales (map, flatMap, orElse, etc.) para trabajar de forma segura.^8

    Desarrollo y ejemplos prácticos

    1. Introducción a la programación funcional

    1.1 ¿Qué es la programación funcional?

    En programación funcional tratamos las funciones como datos de primera clase: se pasan como parámetros, se devuelven y se almacenan en variables. Se favorece el uso de funciones puras (sin efectos secundarios) y estructuras inmutables, lo que reduce bugs por estados compartidos y hace más fácil razonar sobre el código.^4

    En Java 21 esto se materializa en lambdas, interfaces funcionales y la API de Streams, muy usada en código de producción moderno (por ejemplo, en filtros de repositorios, validaciones, reglas de negocio, etc.).^1

    // Ejemplo 1: función "pura" que no modifica estado global
public class FunctionalIntro {

  public static int sumar(int a, int b) {
    return a + b;
  }

  public static void main(String[] args) {
    int resultado = sumar(3, 4);
    System.out.println("Resultado = " + resultado);
  }
}

    // Ejemplo 2: función como dato (interfaz funcional propia)
@FunctionalInterface
interface Operacion {
  int aplicar(int a, int b);
}

public class FunctionalAsData {

  public static void main(String[] args) {
    Operacion suma = (a, b) -> a + b;
    Operacion producto = (a, b) -> a * b;

    System.out.println("Suma: " + suma.aplicar(2, 5));
    System.out.println("Producto: " + producto.aplicar(2, 5));
  }
}

    1.2 Programación imperativa vs funcional

    En la programación imperativa le dices a la máquina cómo hacer las cosas (paso a paso), mientras que en la funcional describes qué quieres y delegas el cómo al framework (Stream API, colectores, etc.).^1

    Tabla de contraste de estilos

    Aspecto Imperativo clásico Funcional con Streams
    Enfoque Secuencia de pasos Declarar transformaciones sobre datos
    Estado Variables mutables Preferencia por inmutabilidad
    Lectura Más detallista pero verbosa Más compacta, tipo “consulta SQL”
    Concurrencia Gestión manual de hilos Más fácil de paralelizar
    Uso con colecciones for/while explícitos stream().filter().map().collect()

    Ejemplo imperativo vs funcional:

    // Ejemplo 1: estilo imperativo
public class ImperativeExample {

  public static void main(String[] args) {
    List<Integer> numeros = List.of(1, 2, 3, 4, 5, 6);
    List<Integer> paresDobles = new ArrayList<>();

    for (Integer n : numeros) {
      if (n % 2 == 0) {
        paresDobles.add(n * 2);
      }
    }

    System.out.println(paresDobles); // [4, 8, 12]
  }
}

    // Ejemplo 2: mismo objetivo con programación funcional
public class FunctionalExample {

  public static void main(String[] args) {
    List<Integer> numeros = List.of(1, 2, 3, 4, 5, 6);

    List<Integer> paresDobles = numeros.stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n * 2)
        .toList();

    System.out.println(paresDobles);
  }
}

    1.3 Ventajas de la programación funcional en Java

    • Código más declarativo y fácil de leer para operaciones con colecciones, como filtrados, agrupaciones y estadísticas.^1
    • Menos estado mutable → menos errores por condiciones de carrera en aplicaciones concurrentes.^3
    • Facilita test unitarios y refactorizaciones, ya que las funciones puras se aíslan bien.^4
    • Encaja con APIs modernas (Spring Data, WebFlux, etc.) que utilizan lambdas y Streams de forma intensiva.^9

    Ejemplo: calcular estadísticas de pedidos de un e‑commerce.

    public class Pedido {
  private final String cliente;
  private final double importe;

  public Pedido(String cliente, double importe) {
    this.cliente = cliente;
    this.importe = importe;
  }

  public String getCliente() {
    return cliente;
  }

  public double getImporte() {
    return importe;
  }
}

public class EstadisticasPedidos {

  public static void main(String[] args) {
    List<Pedido> pedidos = List.of(
        new Pedido("Ana", 100.0),
        new Pedido("Luis", 250.0),
        new Pedido("Ana", 50.0)
    );

    double total = pedidos.stream()
        .mapToDouble(Pedido::getImporte)
        .sum();

    long pedidosDeAna = pedidos.stream()
        .filter(p -> p.getCliente().equals("Ana"))
        .count();

    System.out.println("Total ventas = " + total);
    System.out.println("Pedidos de Ana = " + pedidosDeAna);
  }
}

    return p.getImporte() > 200;

  }

  public static void main(String[] args) {
    List<Pedido> pedidos = // ...
        List.of();

    double totalConDescuento = pedidos.stream()

        .mapToDouble(Double::doubleValue)
        .sum();

}

    1.4 Cuándo usar programación funcional y cuándo no

    No todo debe ser Streams: si se abusa, el código puede volverse críptico o ineficiente. Se recomienda programación funcional para:^3

    • Procesamiento de colecciones donde realizas filtros, mapeos, agrupaciones, agregaciones, etc.^2
    • Transformar datos para APIs (DTOs, JSON, vistas, etc.).^1
    • Lógica de negocio expresable de forma declarativa.

    Evitar o usar con cuidado:

    • Código con mucha mutación de estado global o efectos secundarios (I/O, logs, etc.) dentro de lambdas.^3
    • Zonas de código ultra críticas en rendimiento donde un for simple es más claro y suficiente.^9
    // Ejemplo: buen uso de Streams
public class BuenUsoStreams {

  public static void main(String[] args) {
    List<String> nombres = List.of("Ana", "Luis", "ana", "Marta");

    List<String> unicosOrdenados = nombres.stream()
        .map(String::toUpperCase)
        .distinct()
        .sorted()
        .toList();

    System.out.println(unicosOrdenados);
  }
}

    // Ejemplo: uso quizá excesivo (poco legible)
public class MalUsoStreams {

  public static void main(String[] args) {
    List<Integer> numeros = List.of(1, 2, 3, 4, 5, 6);

    // Esto se podría simplificar con un for o con un método claro
    int resultado = numeros.stream()
        .map(n -> n * 2)
        .filter(n -> n % 3 == 0)
        .map(n -> n - 1)
        .filter(n -> n > 5)
        .mapToInt(Integer::intValue)
        .sum();

    System.out.println("Resultado = " + resultado);
  }
}

    2. Expresiones Lambda

    2.1 ¿Qué es una expresión lambda?

    Una expresión lambda es básicamente una función anónima que puedes pasar como parámetro o almacenar en una variable, implementando una interfaz funcional. En Java su sintaxis básica es:^5

    (parámetros) -> expresión
(parámetros) -> { bloque de código }

    // Ejemplo 1: lambda simple como Runnable
public class LambdaRunnable {

  public static void main(String[] args) {
    Runnable tarea = () -> System.out.println("Ejecutando tarea en hilo");

    new Thread(tarea).start();
  }
}

    // Ejemplo 2: lambda que implementa una interfaz funcional propia
@FunctionalInterface
interface ValidadorNombre {
  boolean esValido(String nombre);
}

public class LambdaValidator {

  public static void main(String[] args) {
    ValidadorNombre noVacio = nombre -> nombre != null && !nombre.isBlank();
    System.out.println(noVacio.esValido("Ana"));
    System.out.println(noVacio.esValido(" "));
  }
}

    2.2 Sintaxis de las lambdas

    Reglas básicas de sintaxis en Java:

    • Si sólo hay un parámetro, se pueden omitir paréntesis (n -> n * 2).^1
    • Si el cuerpo es una sola expresión, se puede omitir {} y return.^1
    • Si hay varias sentencias, se usan {} y return cuando haga falta.^1
    // Ejemplo 1: varias formas de escribir la misma lambda
import java.util.function.Function;

public class LambdaSyntax {

  public static void main(String[] args) {
    Function<Integer, Integer> duplicar1 = (Integer n) -> {
      return n * 2;
    };

    Function<Integer, Integer> duplicar2 = (n) -> n * 2;

    Function<Integer, Integer> duplicar3 = n -> n * 2;

    System.out.println(duplicar1.apply(10));
    System.out.println(duplicar2.apply(10));
    System.out.println(duplicar3.apply(10));
  }
}

    // Ejemplo 2: lambdas con varios parámetros
import java.util.function.BiFunction;

public class LambdaBiFunction {

  public static void main(String[] args) {
    BiFunction<Integer, Integer, Integer> max =
        (a, b) -> a > b ? a : b;

    System.out.println(max.apply(3, 5));
  }
}

    Tip

    Usa tipos inferidos (n -> n * 2) salvo que la firma no quede clara; así el código queda más limpio y legible.^5

    2.3 Lambdas con una y varias líneas

    • Lambdas de una línea → ideales para operaciones simples (map, filter, etc.).^1
    • Lambdas de varias líneas → útiles si necesitas lógica más compleja, logs, validación, etc.^1
    // Ejemplo 1: lambda una línea en Streams
import java.util.List;

public class LambdaOneLine {

  public static void main(String[] args) {
    List<Integer> numeros = List.of(1, 2, 3, 4, 5);

    numeros.stream()
        .map(n -> n * n) // cuadrado
        .forEach(System.out::println);
  }
}

    // Ejemplo 2: lambda multilínea
import java.util.List;

public class LambdaMultiLine {

  public static void main(String[] args) {
    List<Integer> numeros = List.of(-2, -1, 0, 1, 2);

    numeros.stream()
        .map(n -> {
          System.out.println("Procesando: " + n);
          int valorAbsoluto = Math.abs(n);
          return valorAbsoluto;
        })
        .forEach(System.out::println);
  }
}

    2.4 Uso de lambdas con colecciones

    Las lambdas brillan cuando las combinas con colecciones y Streams.^2

    // Ejemplo 1: filtrar y transformar una lista de usuarios
public class Usuario {
  private final String nombre;
  private final boolean activo;

  public Usuario(String nombre, boolean activo) {
    this.nombre = nombre;
    this.activo = activo;
  }

  public String getNombre() {
    return nombre;
  }

  public boolean isActivo() {
    return activo;
  }
}

public class LambdasConColecciones {

  public static void main(String[] args) {
    List<Usuario> usuarios = List.of(
        new Usuario("Ana", true),
        new Usuario("Luis", false),
        new Usuario("Marta", true)
    );

    List<String> nombresActivos = usuarios.stream()
        .filter(Usuario::isActivo)
        .map(Usuario::getNombre)
        .toList();

    System.out.println(nombresActivos);
  }
}

    // Ejemplo 2: ordenar con lambdas
import java.util.Comparator;

public class OrdenarConLambdas {

  public static void main(String[] args) {
    List<String> nombres = new ArrayList<>(List.of("Luis", "Ana", "Marta"));

    nombres.sort((a, b) -> a.compareToIgnoreCase(b));
    System.out.println("Orden alfabético: " + nombres);

    nombres.sort((a, b) -> Integer.compare(a.length(), b.length()));
    System.out.println("Orden por longitud: " + nombres);
  }
}

    2.5 Variables efectivamente finales

    Las lambdas en Java sólo pueden capturar variables que sean final o efectivamente finales (no se modifican después de inicializarse). Esto evita que una lambda dependa de estados externos cambiantes impredecibles.^2

    // Ejemplo 1: variable efectivamente final
import java.util.function.Consumer;

public class EfectivamenteFinal {

  public static void main(String[] args) {
    String prefijo = "[DEBUG] ";

    Consumer<String> log = mensaje -> System.out.println(prefijo + mensaje);

    log.accept("Arrancando servidor");
  }
}

    // Ejemplo 2: intento de modificar variable capturada (error de compilación)
public class NoCompila {

  public static void main(String[] args) {
    int contador = 0;

    Runnable r = () -> {
      // contador++;  // ERROR: variable no es efectivamente final
      System.out.println("contador = " + contador);
    };

    r.run();
  }
}

    3. Interfaces funcionales

    3.1 ¿Qué es una interfaz funcional?

    Una interfaz funcional es una interfaz con un único método abstracto que puede representarse con una expresión lambda o una referencia a método. Java incluye muchas en java.util.function para cubrir casos típicos como transformar, consumir, producir valores o evaluar predicados.^6

    // Ejemplo 1: interfaz funcional propia
@FunctionalInterface
interface TransformadorTexto {
  String aplicar(String texto);
}

public class InterfazFuncionalPropia {

  public static void main(String[] args) {
    TransformadorTexto mayusculas = String::toUpperCase;
    System.out.println(mayusculas.aplicar("hola daw"));
  }
}

    // Ejemplo 2: uso en método de orden superior
public class ProcesadorTextos {

  public static String procesar(String texto, TransformadorTexto transformador) {
    return transformador.aplicar(texto);
  }

  public static void main(String[] args) {
    String resultado = procesar("hola daw", t -> "*** " + t + " ***");
    System.out.println(resultado);
  }
}

    3.2 Anotación @FunctionalInterface

    @FunctionalInterface marca explícitamente que una interfaz debe tener sólo un método abstracto, y el compilador fallará si añades otro. Aun así, se permiten métodos default y static porque no cuentan como abstractos.^5

  default int sumar(int a, int b) {
    return a + b;
  }

  static void log(String mensaje) {
    System.out.println("[LOG] " + mensaje);
  }
}

    4. Introducción a Streams

    4.1 ¿Qué es un Stream?

    Un Stream es una secuencia de elementos sobre la que defines un pipeline de operaciones intermedias y una terminal. No almacena los datos: se apoya en una fuente (colección, array, generador, etc.) y los procesa de forma perezosa hasta que llamas a una operación terminal.^2

    long cantidadPares = numeros.stream()
        .filter(n -> n % 2 == 0)
        .count();

    System.out.println("Pares = " + cantidadPares);
  }
}

    String v2 = vacio.orElseGet(OptionalOrElse::valorPorDefectoCaro);

    System.out.println(v1);
    System.out.println(v2);
  }
}

    // Ejemplo 3: orElseThrow
import java.util.NoSuchElementException;
import java.util.Optional;

public class OptionalOrElseThrow {

  public static void main(String[] args) {
    Optional<String> vacio = Optional.empty();

    try {
      String valor = vacio.orElseThrow(
          () -> new NoSuchElementException("No se encontró el valor"));
      System.out.println(valor);
    } catch (NoSuchElementException e) {
      System.out.println("Error: " + e.getMessage());
    }
  }
}

    Aplicación en el mundo real

    En aplicaciones web modernas con Java 21 y frameworks como Spring Boot, la programación funcional y los Streams son omnipresentes: filtros de seguridad, validación de inputs, transformación de entidades a DTOs, agregación de datos para informes, etc. En un microservicio de e‑commerce podrías:^9

    • Usar Streams para procesar listas de pedidos, calcular totales por cliente, estados y fechas.^7
    • Combinar groupingBy y counting para generar dashboards de negocio sin tener que escribir SQL complejo en cada capa.^7
    • Aprovechar Optional para dejar claro cuándo un recurso puede no existir (404) y evitar cascadas de NullPointerException en la lógica de negocio.^8

    En entornos con mucha carga (procesamiento de logs, estadísticas en tiempo real, etc.) los Streams paralelos pueden dar un extra de rendimiento, siempre que el trabajo sea CPU‑bound y las operaciones sean independientes. En definitiva, dominar programación funcional y Streams te acerca al estilo de código que se espera en equipos profesionales Java actuales.^9
