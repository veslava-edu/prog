    8 - Programación funcional y Streams

    Introducción: La cadena de montaje de software

    Imagina que eres el chef de un restaurante de comida rápida. En el enfoque tradicional (imperativo), tú haces todo: coges una patata, la pelas, la cortas, calientas el aceite, la fríes, le echas sal y la pones en el plato. Si quieres hacer 100 raciones, repites ese ciclo 100 veces, paso a paso, gestionando tú mismo el estado de cada patata. Agotador, ¿verdad?

    La Programación Funcional y los Streams son como montar una cadena de producción industrial. Tú diseñas la tubería: "Aquí entra materia prima, aquí hay un robot que descarta las patatas podridas (filtro), aquí otro que las corta (transformación), y al final caen en cajas (colección)". Una vez montada la cinta, tú solo vuelcas el camión de patatas al principio y esperas el resultado al final. No te importa cómo se corta cada patata individualmente, solo te importa que la configuración de la máquina sea la correcta.

    Como vimos en el Tema 7 (Estructuras de Datos), antes recorríamos las listas con bucles for y iterators. Ahora, vamos a dejar de decirle al ordenador cómo iterar paso a paso, y empezaremos a decirle qué queremos conseguir.

    1. Introducción a la Programación Funcional

    1.1. ¿Qué es la programación funcional?

    Definición: Programación Funcional

    Es un paradigma de programación declarativo donde los programas se construyen aplicando y componiendo funciones. Se basa en tratar el cálculo como la evaluación de funciones matemáticas y evita el estado mutable y los efectos secundarios.

    En Java, no es un paradigma exclusivo (Java es un lenguaje híbrido orientado a objetos), pero desde Java 8 (y mejorado en Java 21), tenemos herramientas poderosas para escribir código más limpio y seguro.

    1.2. Programación imperativa vs funcional

    • Imperativa: Te centras en el CÓMO. Escribes los pasos exactos y el flujo de control (bucles, cambios de variables).
    • Funcional (Declarativa): Te centras en el QUÉ. Describes el resultado deseado sin especificar explícitamente los pasos paso a paso.

    Comparativa Rápida:

    Característica Imperativo (El viejo estilo) Funcional (El estilo moderno)
    Foco Cómo hacer las cosas (algoritmos paso a paso). Qué queremos obtener.
    Estado Mutable (las variables cambian constantemente). Inmutable (se crean nuevos valores en lugar de cambiar los viejos).
    Efectos Efectos secundarios comunes (cambiar variables globales). Sin efectos secundarios (funciones puras).
    Unidad Principal Objetos y métodos. Funciones y lambdas.
    Iteración Bucles (for, while). Recursividad o Streams API.

    1.3. Ventajas de la programación funcional en Java

    1. Código más conciso: Menos "código espagueti" y boilerplate.
    2. Menos errores: Al evitar cambiar el estado de las variables (inmutabilidad), se reducen los bugs de concurrencia y lógica.
    3. Paralelización sencilla: Procesar datos en múltiples núcleos de la CPU es trivial con Streams.
    4. Testeabilidad: Las funciones puras son muy fáciles de testear unitariamente.

    1.4. Cuándo usar programación funcional y cuándo no

    Consejo de Senior

    Usa el estilo funcional para transformación de datos, filtrado de listas y cálculos complejos sobre colecciones. Sigue usando el estilo imperativo/OO para la arquitectura general de la aplicación, gestión de entidades y lógica de negocio muy compleja que requiera muchos cambios de estado.

    graph TD
    A[Problema: Procesar Lista de Usuarios] --> B{¿Necesito transformar/filtrar datos?}
    B -- Sí --> C[Usa Streams y Lambdas (Funcional)]
    B -- No, es lógica de control compleja --> D[Usa Bucles y Condicionales (Imperativo)]
    C --> E[Código más limpio y legible]
    D --> F[Control total del flujo]

    2. Expresiones Lambda

    2.1. ¿Qué es una expresión lambda?

    Definición: Expresión Lambda

    Es una función anónima (sin nombre) que se puede tratar como un valor. Puedes pasarla como argumento a un método o guardarla en una variable. Es la forma que tiene Java de decir: "Aquí tienes un trozo de código, ejecútalo cuando lo necesites".

    Piensa en las lambdas como "funciones de usar y tirar" o atajos sintácticos para implementar interfaces que solo tienen un método.

    2.2. Sintaxis de las lambdas

    La sintaxis básica es la de la "flecha": (parámetros) -> { cuerpo }.

    // Estilo antiguo (Clase anónima) - ¡Mucho ruido visual!
Runnable r1 = new Runnable() {
    @Override
    public void run() {
        System.out.println("Corriendo al estilo antiguo");
    }
};

// Estilo Lambda - Limpio y directo
Runnable r2 = () -> System.out.println("Corriendo con Lambda");

    2.3. Lambdas con una y varias líneas

    Java es inteligente (inferencia de tipos). A menudo no necesitas especificar los tipos de los parámetros ni usar llaves si es una sola línea.

    Ejemplos:

    // 1. Sin parámetros, una línea
() -> System.out.println("Hola Mundo");

// 2. Un parámetro (paréntesis opcionales), una línea (return implícito)
x -> x * x; 

// 3. Varios parámetros, una línea
(x, y) -> x + y;

// 4. Con tipos explícitos (opcional, pero a veces útil)
(Integer x, Integer y) -> x + y;

// 5. Varias líneas (llaves y return obligatorios)
(x, y) -> {
    System.out.println("Sumando " + x + " y " + y);
    return x + y;
};

    2.4. Uso de lambdas con colecciones

    El uso más común es con métodos como forEach o sort.

    Record Java 14+

    Usamos record aquí, una característica moderna de Java para crear clases inmutables de datos rápidamente.

    // Definimos un record simple (Java 16+)
record Producto(String nombre, double precio) {}

public class EjemploLambda {
    public static void main(String[] args) {
        List<Producto> lista = new ArrayList<>();
        lista.add(new Producto("Portátil", 1000.0));
        lista.add(new Producto("Ratón", 25.5));
        lista.add(new Producto("Teclado", 45.0));

        // Ordenar usando Lambda (Comparator)
        // (p1, p2) son inferidos como tipo Producto automáticamente
        lista.sort((p1, p2) -> Double.compare(p1.precio(), p2.precio()));

        // Iterar usando Lambda (Consumer)
        lista.forEach(p -> System.out.println("Producto: " + p.nombre()));
    }
}

    2.5. Variables efectivamente finales

    ¡Cuidado con el Scope!

    Las lambdas pueden usar variables que están definidas fuera de ellas (en el método que las contiene), PERO esas variables deben ser finales o efectivamente finales.

    Esto significa que no puedes cambiar el valor de una variable local dentro de una lambda, ni tampoco cambiarla fuera después de haber definido la lambda.

    int factor = 2;
// factor = 3; // Si descomentas esto, la línea de abajo fallará al compilar.

List<Integer> numeros = List.of(1, 2, 3);
numeros.forEach(n -> System.out.println(n * factor)); // OK
// numeros.forEach(n -> factor++); // ERROR: No se puede modificar 'factor' dentro

    3. Interfaces Funcionales

    3.1. ¿Qué es una interfaz funcional?

    Definición: Interfaz Funcional

    Es una interfaz que tiene EXACTAMENTE UN método abstracto. Puede tener métodos default o static, pero solo uno abstracto. Son el "molde" donde encajan las expresiones lambda.

    3.2. Anotación @FunctionalInterface

    Es una buena práctica anotar tus interfaces funcionales con @FunctionalInterface. No es obligatorio, pero si lo pones, el compilador te avisará si por error añades un segundo método abstracto.

    @FunctionalInterface
public interface Operacion {
    int ejecutar(int a, int b);
    // int otroMetodo(); // Esto daría error de compilación
}

    3.3. Interfaces funcionales más usadas en Java

    El paquete java.util.function tiene las herramientas básicas. No reinventes la rueda, usa estas:

    Interfaz Firma del método Descripción Mnemotecnia
    Predicate<T> boolean test(T t) Recibe un objeto y devuelve true/false. El "Portero de discoteca" (pasa o no pasa).
    Function<T, R> R apply(T t) Recibe un objeto T y devuelve un objeto R. La "Fábrica" (entra materia, sale producto).
    Consumer<T> void accept(T t) Recibe un objeto y no devuelve nada. El "Agujero negro" (se traga el dato).
    Supplier<T> T get() No recibe nada y devuelve un objeto. El "Proveedor" (genera datos de la nada).

    3.4. Ejemplos prácticos de cada interfaz

    import java.util.function.*;
import java.util.*;

public class InterfacesFuncionalesDemo {
    public static void main(String[] args) {

        // 1. PREDICATE: Validar si un número es par
        Predicate<Integer> esPar = num -> num % 2 == 0;
        System.out.println("¿Es 4 par? " + esPar.test(4)); // true

        // 2. FUNCTION: Convertir String a su longitud
        Function<String, Integer> longitud = texto -> texto.length();
        System.out.println("Longitud de 'Java': " + longitud.apply("Java")); // 4

        // 3. CONSUMER: Imprimir un mensaje con formato
        Consumer<String> impresor = msg -> System.out.println("LOG: " + msg);
        impresor.accept("Sistema iniciado"); // LOG: Sistema iniciado

        // 4. SUPPLIER: Generar un número aleatorio
        Supplier<Double> aleatorio = () -> Math.random();
        System.out.println("Random: " + aleatorio.get());
    }
}

    4. Introducción a Streams

    4.1. ¿Qué es un Stream?

    Definición: Stream

    Un Stream (flujo) es una secuencia de elementos que admite operaciones secuenciales y paralelas. NO ES una estructura de datos; no almacena datos. Es un canal por donde pasan los datos para ser procesados.

    Imagina un Stream como una tubería de agua. La colección es el tanque de agua. Tú conectas la tubería al tanque, pones filtros y calentadores en medio, y al final recoges el agua tratada en un vaso.

    4.2. Diferencias entre colecciones y streams

    Colección (List, Set...) Stream
    Almacena datos en memoria. No almacena datos (los mueve).
    Estático: Los datos ya están ahí. Dinámico/Lazy: Los datos se calculan/traen bajo demanda.
    Iteración Externa: Tú controlas el bucle for. Iteración Interna: El Stream gestiona el recorrido.
    Se puede recorrer múltiples veces. Se consume una sola vez.

    Stream de un solo uso

    Si intentas reutilizar un stream que ya ha terminado (operación terminal), obtendrás una excepción IllegalStateException.

    4.3. Creación de streams

    Desde Colecciones: 

    List<String> lista = List.of("A", "B", "C");
Stream<String> streamLista = lista.stream();

    Desde Arrays: 

    String[] array = {"X", "Y", "Z"};
Stream<String> streamArray = Arrays.stream(array);

    Directamente (Stream.of): 

    Stream<Integer> streamNumeros = Stream.of(1, 2, 3, 4, 5);

    4.4. Streams secuenciales y paralelos

    Por defecto, los streams son secuenciales (un solo hilo). Pero una de las grandes magias de Java es .parallelStream().

    // Procesa usando múltiples núcleos de la CPU automáticamente
lista.parallelStream().forEach(item -> procesarPesado(item));

    Cuidado con Parallel

    No uses parallelStream() por defecto. Solo úsalo si tienes muchísimos datos o el procesamiento de cada elemento es muy lento. Para listas pequeñas, la gestión de hilos hace que sea más lento que el secuencial.


    Reflexiona

    1. Si tienes un ArrayList con 10 elementos, ¿tiene sentido convertirlo a parallelStream?

    5. Operaciones Intermedias

    5.1. Características

    Son perezosas (lazy). Si escribes lista.stream().filter(...), Java no hace nada todavía. Solo toma nota de que "cuando alguien pida resultados, tendré que filtrar". Devuelven otro Stream, permitiendo encadenar métodos (Fluent API).

    5.2. filter()

    Recibe un Predicate. Deja pasar solo los elementos que devuelven true.

    List<Integer> numeros = List.of(1, 5, 10, 15, 20);
// Filtrar mayores de 10
numeros.stream()
       .filter(n -> n > 10) 
       .forEach(System.out::println); // Salida: 15, 20

    5.3. map()

    Recibe una Function. Transforma cada elemento en otra cosa (puede cambiar el tipo).

    List<String> nombres = List.of("ana", "pepe");
// Transformar a mayúsculas
nombres.stream()
       .map(s -> s.toUpperCase())
       .forEach(System.out::println); // Salida: ANA, PEPE

    5.4. flatMap()

    Aplanando listas

    Útil cuando tienes una lista de listas y quieres una sola lista continua con todos los elementos.

    Recibe una función que devuelve un Stream y los "aplana" (flatten) en un único nivel.

    List<List<String>> aula = List.of(
    List.of("Juan", "Maria"),
    List.of("Pedro", "Lucia")
);

// Queremos un stream con los 4 nombres, no un stream de 2 listas
aula.stream()
    .flatMap(lista -> lista.stream())
    .forEach(System.out::println); // Juan, Maria, Pedro, Lucia

    5.5. sorted()

    Ordena el stream. Puede ser orden natural o con un Comparator.

    Stream.of("Banana", "Apple", "Cherry")
      .sorted() // Alfabético por defecto
      .forEach(System.out::println); // Apple, Banana, Cherry

    5.6. distinct()

    Elimina duplicados (usa equals() y hashCode()).

    Stream.of(1, 2, 2, 3, 1)
      .distinct()
      .forEach(System.out::print); // 123

    5.7. limit() y skip()

    • limit(n): Se queda con los primeros n elementos.
    • skip(n): Ignora los primeros n elementos.
    // Paginación simple
Stream.iterate(1, n -> n + 1) // Stream infinito 1, 2, 3...
      .skip(10) // Saltamos los 10 primeros
      .limit(5) // Cogemos los 5 siguientes
      .forEach(System.out::print); // 1112131415

    6. Operaciones Terminales

    6.1. Características

    Son ansiosas (eager). Disparan el procesamiento de toda la tubería. Cierran el stream y devuelven un resultado concreto (una lista, un entero, un booleano o void).

    6.2. forEach()

    Ejecuta una acción para cada elemento. Ojo: no garantiza orden en streams paralelos.

    6.3. collect()

    La más importante. Convierte el stream en una colección o estructura final. (Veremos más en el punto 7).

    6.4. count()

    Devuelve un long con la cantidad de elementos.

    long cantidad = Stream.of("A", "B", "C").count(); // 3

    6.5. anyMatch(), allMatch(), noneMatch()

    Reciben un Predicate y devuelven boolean. Son de cortocircuito (si anyMatch encuentra uno true, deja de procesar el resto).

    boolean hayAlgunPar = Stream.of(1, 3, 5, 6).anyMatch(n -> n % 2 == 0); // true

    6.6. findFirst() y findAny()

    Devuelven un Optional (porque el stream podría estar vacío después de filtrar).

    6.7. reduce()

    La navaja suiza

    Reduce toma una secuencia de elementos y los combina en un solo valor aplicando repetidamente una operación. Es como "plegar" el stream.

    List<Integer> precios = List.of(10, 20, 30);

// Sumar todos los precios
// 0 es el valor inicial (identidad)
// (a, b) -> a + b es el acumulador
int total = precios.stream()
                   .reduce(0, (subtotal, elemento) -> subtotal + elemento);
// total = 60


    Reflexiona

    1. ¿Cuál es la diferencia entre map y flatMap? Pon un ejemplo de la vida real (ej. cajas dentro de cajas).
    2. Si usas filter y luego findFirst, ¿el stream procesa todos los elementos de la lista original? (Pista: piensa en la eficiencia).

    7. Collectors

    7.1. ¿Qué es un Collector?

    Es una receta para empaquetar los elementos resultantes del stream. Se usan dentro del método .collect(). La clase java.util.stream.Collectors (fíjate en la 's' final) es una fábrica de collectors útiles.

    7.2. toList(), toSet(), toMap()

    Recoger en colecciones estándar.

    // Java 16+ tiene un método directo .toList() en el stream que devuelve una lista inmutable
List<String> lista = stream.toList(); 

// Para Set o Map usamos Collectors
Set<String> conjunto = stream.collect(Collectors.toSet());

    7.3. Collectors.groupingBy()

    Similar al GROUP BY de SQL. Devuelve un Map.

    record Persona(String nombre, String ciudad) {}

List<Persona> gente = List.of(
    new Persona("Pepe", "Madrid"),
    new Persona("Ana", "Barcelona"),
    new Persona("Luis", "Madrid")
);

// Agrupar por ciudad: Map<String, List<Persona>>
var porCiudad = gente.stream()
                     .collect(Collectors.groupingBy(Persona::ciudad));

// Resultado: { "Madrid": [Pepe, Luis], "Barcelona": [Ana] }

    7.4. Collectors.partitioningBy()

    Caso especial de agrupación donde la clave es Boolean. Divide el stream en dos: los que cumplen la condición y los que no.

    // Separar mayores de edad y menores
var particion = gente.stream()
                     .collect(Collectors.partitioningBy(p -> p.edad >= 18));

    7.5. Collectors.joining()

    Une Strings. Muy útil para generar CSV o logs.

    String nombres = gente.stream()
                      .map(Persona::nombre)
                      .collect(Collectors.joining(", ", "[", "]"));
// Resultado: "[Pepe, Ana, Luis]"

    7.6. Estadísticas (counting, summing, averaging)

    double precioMedio = productos.stream()
                              .collect(Collectors.averagingDouble(Producto::precio));

    8. Optional

    8.1. Problemas del null

    Tony Hoare, el inventor de la referencia nula, lo llamó su "error del billón de dólares". NullPointerException es la pesadilla de Java.

    8.2. ¿Qué es Optional?

    Optional<T> es una caja que puede contener un valor no nulo o estar vacía. Te obliga a pensar: "Oye, puede que aquí no haya nada, ¿qué hacemos?".

    8.3. Creación y uso

    // Crear
Optional<String> vacio = Optional.empty();
Optional<String> conValor = Optional.of("Hola");
Optional<String> dudoso = Optional.ofNullable(null); // Crea un empty de forma segura

// Usar de forma segura
String resultado = dudoso.orElse("Valor por defecto");

// Ejecutar si existe
conValor.ifPresent(val -> System.out.println("Tengo: " + val));

    8.4. Métodos principales (Java 21)

    • isPresent() / isEmpty(): Verificación booleana.
    • orElse(T other): Dame el valor o este defecto.
    • orElseThrow(): Dame el valor o lanza excepción (mejor que get() porque el nombre avisa).
    • ifPresentOrElse(action, emptyAction): Si está, haz esto; si no, haz esto otro.
    buscarUsuario("admin")
    .ifPresentOrElse(
        u -> System.out.println("Usuario encontrado: " + u),
        () -> System.out.println("Usuario no existe, creando uno nuevo...")
    );


    Aplicación en el Mundo Real

    1. Big Data y Procesamiento de Logs: Herramientas como Apache Spark o Kafka Streams funcionan conceptualmente igual que los Streams de Java. Aprender esto es la base para la ingeniería de datos.
    2. Backends Reactivos: Frameworks modernos como Spring WebFlux o Quarkus usan conceptos funcionales (Reactor/Mutiny) para manejar miles de peticiones simultáneas con pocos recursos.
    3. Clean Code: En el trabajo diario, verás que cambiar bucles anidados de 20 líneas por una cadena de streams de 4 líneas hace que el código sea mucho más fácil de leer y mantener por tus compañeros.
